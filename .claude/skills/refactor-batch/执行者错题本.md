# 执行者错题本（refactor-batch 附册）

> 执行者/子代理真实踩过的坑，每批开工前读。一条一行：坑 → 规矩；过程细节在 git 历史（`git log -p -- <本文件>`）。新坑记回来，编号只增不改（缺号＝已过时删除）。同类满三条，按 `SKILL.md`「守卫准入」判断要不要收成守卫。

## 守卫与断言
- **E1 方法体正则守卫走 `methodBody()` + `stripComments()` 共享 helper**（`scripts/check-structure.mjs`）：裸写正则会被注释喂假绿。
- **E10 取真源断言要对「剥注释后的函数体」匹配**：helper 返回原始切片时，把保护代码注释掉断言照样绿。
- **E18 路径豁免先 `relative(ROOT, file)` 再匹配**：worktree 住在 `.claude/worktrees/` 下，拿绝对路径匹配 dot 目录会把 worktree 里全部活文件豁免掉；守卫落地后要在 worktree 里做一次真违例咬红。
- **E27 立/审守卫先问「扫描面覆盖目标文件类型了吗」**：`walk()` 默认只扫 js/ts/vue，wxml/wxss/json 层失明（占位店名因此活到了生产）。扩面用可选参数、默认值不变；wxml 注释 `<!-- -->` 要另剥。守卫报错里点名的「单源」不代表它真存在。
- **E32 文本级形状断言先截出目标函数体再匹配，禁全文匹配**：同文件另一处同形代码会喂假绿。

## 反向自检（篡改 → 验红 → 还原）
- **E14 篡改后先 `grep -c` 确认真改到了，再信红绿**：perl 就地替换可能静默没命中，被误读成「守卫是摆设」。
- **E19 还原同样要 grep 验证落地**；perl 还原失败一次就改用精确 Edit 或带 assert 的 python replace。
- **E21 篡改/还原的锚点必须在文件内唯一**：同款行 >1 时 `replace(...,1)` 会改错地方，还原又插到错位置。先数同款行；还原后 `git diff` 逐字核对。
- **E17 篡改要覆盖全部调用点，接线断言要先剥 import**：先 `grep -c '<名>('` 数清，删就删光（只删一处时守卫理应仍绿）；断言用 `名(` 且在剥掉 import 的正文上跑，否则光留 import 照样绿。
- **E13 还原用与篡改对称的精确编辑，不用 `git checkout -- <file>`**：它会连本批未提交改动一起冲掉。

## 共享工作区与并行
- **E12 只读评审员/验证者禁用 git checkout/restore/stash**：验证性篡改「自己备份 → 自己 cp 回写」。
- **E23 给子代理的 prompt 凡涉共享工作区，显式写「禁 git checkout/restore/stash，对照基线用 scratchpad 副本」**；看到「文件被还原」怪象，先用 `git log` + `git status` + grep 三点取证，怀疑并行方的瞬态窗口。
- **E11 新 worktree 先 `npm install`**：借到主仓的包会「半绿」，比全红更误导；篡改未跟踪新文件后 `git checkout` 还原不了。
- **E24 开工先 `git fetch`，`git log HEAD..origin/main` 有输出就先 rebase**：本地可能落后几十个提交却毫无征兆；编号型引用、「某文件在不在」的断言一律以 rebase 后的树为准。

## 写代码与改规格
- **E2 抄既有模式要抄全两半**：wxml 事件绑定与 ts 方法定义是一对，抄一半真机报错。
- **E4 金额跨界显式换算**：mp 购物车/展示层是「元」，云端与订单链路是「分」（`Fen`）。
- **E5 规格矛盾或歧义 → 记 openQuestions 停手**，不脑补。
- **E7 勾销债目前当场重新 grep**，不沿用上一批的核实结论。
- **E15 编号型引用（决策§N / 病根#N / R-N）落笔前先查目标文件现值**，别凭记忆写。
- **E16 改共享函数前 `grep -rn` 列全调用点**，逐个问要新行为还是旧行为；新行为显式 opt-in、默认旧行为；「隔离」承诺要落成守卫或测试，不能只写在注释里。
- **E20 受限运行时（.wxs 等）写代码前先查语法子集**：WXS 是 ES5 子集，`Number/String` 不可调用、无箭头/let/模板串/try；在 Node 里跑绿的对拍测试不算证据，要另配静态守卫。两侧同式时都写受限侧合法式。
- **E22 平台回调的载荷形状要实测**：先把整个入参打到控制台看；`|| 0` 之类兜底会把「读错字段」伪装成「值就是 0」。能插一行 log 就别推断三轮。
- **E29 同一个样式属性只能有一个写入方**：WXS `setStyle` 写过的属性，wxml `style` 数据绑定就永久失灵；要验就量真实渲染几何，且验「后续更新还生效吗」。
- **E31 `Object.assign(Object.create(null), {…})` 结果是 any，会吃掉类型检查**：字面量配 `satisfies Record<…>`；改坏一个签名 `tsc` 必须红。
- **E33 tab 首屏上屏字要在品牌字体 tier1 子集里**：往 home/cart/me 加中文前用 `assets/brand-fonts/tier1.txt` 对每个新字；缺字就换字或放二级页，别改 txt。
- **E34 mp 测试不能用 Node 读文件**（`node:fs`、`import.meta.url` 会让 typecheck 红）：扫 `.wxml` 的断言放 `rewrite/cloud/tests/`。

## 验证与定级
- **E25 报「会造成 X 损失」前沿链路找兜底闸**：`grep -rn '<关键状态字段>'` 过一遍服务端校验、状态机闸、幂等键，找到就如实降级。
- **E26 浮层可见性不靠单点 `elementFromPoint`**：逐子项打点或看截图，探针与截图矛盾以截图为准。程序化 `scrollBy` 可能不派发 scroll 事件，别把环境怪癖当代码 bug。
- **E28 开发者工具里清 storage 后立刻 `cli quit`，退出时内存副本会写回来**：清数据走产品自己的删除路径，清完读回断言。
- **E30 固定日期的测试种子 + 随墙钟滑动的默认窗口 = 时间炸弹**：这类调用显式传 `from/to` 钉在种子上，或种子用 `Date.now() - offset`。

## 开发者工具自动化与提交闸
- **E35 自动模式下红区文件的 `RED_ALLOWED=1 git commit` 会被分类器整条拒掉（连同链里的 push / pr create）**：别在一条命令里把提交和推送/建 PR 串起来；红区批准备好提交信息文件 + 一条脚本交老板亲手跑，自己只做非红区提交。
- **E36 `miniprogram-automator` 的 `evaluate` 不认 `async` 函数（序列化后语法错「missing ) after argument list」）**：用 Promise 链；逻辑层探针走 `require('lib/xxx.js')` 包模块导出，别包组件原型（每个组件定义各一份原型）。
- **E37 IDE 一个项目窗口都没有时 `cli auto` 挂死不回；改了源码想确认跑的是新包要 `cli quit` 后冷启（自动编译不可信）**：换项目 `cli close --project A` → `cli auto --project B --auto-port 9421`（9420 是 IDE HTTP 服务口，自动化口必须另选）。
