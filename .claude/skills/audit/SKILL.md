# 体检

> 周期审查：换一双眼睛找机器够不到的问题。**验证，不是相信**。

## 开圈前
1. `git fetch` 后对 `origin/main` 看（本地可能落后）；`git status --short` 非空先停下报告，不卷别人半成品。
2. 跑 `npm run check`。绿只说明已建模的规则没违例，本圈找的是机器够不到的。
3. 选面：用户点名哪面就只跑哪面；说「全面体检」就三面都跑，可派只读子代理并行扫，但结论一律亲核。

## 代码面（按 P0→P3）
P0 崩溃/数据错乱/交易错误/安全 ｜ P1 主流程错/状态不一致 ｜ P2 维护成本/重复 ｜ P3 风格/命名。逐行读真实现，不凭记忆：
- **交易链**：createOrder（库内价二次校验、数量上限、分整数）→ pay → payCallback/refundCallback（防伪、金额核验 fail-closed）→ 退款（分摊 ≤ 实付、确定性 `_id`）。
- **安全闸**：kit 闸是否 fail-closed；写库点是否都过闸。
- **状态机**：转移走 `transition()`；一次性副作用绑首次转移。
- **失败可见**：失败有没有装成空、装成功（病根#14）——这是审查最常抓到的一类。
- **病根覆盖**：`npm run report` 看病根地图，每条病根要么有守卫，要么在 `CLAUDE.md` 有 `[靠人:#N]` 锚。
- **够不到的老实标**：库集合权限、云存储私有读、真支付退款、真机——列为「上线前控制台 + 真机核」。

## 文档面（文档说的 vs 真实）
- 先取真值再读文档：`git log -20 --oneline`、代码、`cloudbaserc.json`、`npm run report`。没有真值对照，只会复读文档。
- 重点抓：已被 commit 解决却没回写的状态、手抄的名字/数字/守卫名（对代码 grep 核，不存在即假）、该删没删的过程账。
- 文档与 commit 打架，以 commit 为准。
- 别过度砍：项目自己的决定和理由要留；通用教程、官方文档复述可删。判别法：「这段你会去别处查吗？」会就删，不会就留。

## 清淤面（信息层的债）
- **死指针**：引用的文件、npm script、云函数、集合、守卫名不存在。
- **孤儿**：全仓 grep 零引用的脚本或文档（运维手册提到的算有引用）。删前再 grep 一遍。
- **双源漂移**：同一件事在两处说法不一，留正册，其余改一行指针。
- **过期断言**：「TODO/将要」已做完、「已上线」查无此事、「剩 N 天/当前 N 个」这类会腐烂的数字，一律改成「以某命令为准」。
- 不删业务预留：先 grep `docs/关键决策记录.md` 和 `docs/需求清单.md`，对得上号的留着。

## 每条 finding 的处置
- **亲核**：子代理会误数、高估、记错上下文，逐条对代码/git 核实，核不实的丢弃。
- **三选一**：真风险类（钱/权限/状态、手抄副本）按 `/refactor-batch` 的「守卫准入」考虑加守卫；判断题改文本；过期内容直接删（git 即归档层）。
- 落地走 `/refactor-batch`。一圈没找到真问题就报「跑了、验了、干净」，负结果也是交付。

## 产出
分级 findings 表，每条带「文件:行号 + 证据 + 真值来源」和状态：已修 / 延后（给理由）/ 刻意 / 够不到（人工核）。用业务语言汇报，结论先行，不吹。

## 红线
- 不部署、不动云端（数据库、控制台、工作流）。体检只在仓内。
- 动钱、不可逆、口径未定的，先问老板。
