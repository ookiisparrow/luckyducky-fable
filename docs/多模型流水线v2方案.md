# 多模型运维流水线 v2.2 方案

日期: 2026-08-10 · 状态: ✅ 已定稿（三轮交叉验证通过: codex✓ kimi✓）
基于: v1 + 第一轮交叉审查 + v2 + 第二轮争议反驳 + v2.1 + 第三轮判定分歧 → v2.2 小修后双票通过

> 结构: 每节分两层——
> 【意图】要达成的目标（不绑定实现）
> 【最低约束】两轮审查要求必须满足的底线（可验收, 否则安全属性无法验证）

---

## 0. 定位

单人长期维护小程序项目（微信小程序 + 云开发后端 + 管理后台），
三家模型（deepseek/kimi/chatgpt）在 herdr 多面板中组成交叉验证流水线。

服从项目既有硬约束（AGENTS.md 体系，v2.1 明确衔接）:
- red 模块（订单钱链/运维观测）/部署/数据库不可逆操作 = 恒禁, 先问老板
- 确定性验收 = check 全绿, 裁判（检查脚本）不可被球员改写
- 工单纪律: 有编号、单源、不自派任务
- 双轨锁: 未明说切换前不触发切换动作

## 1. 模型角色路由

【意图】按任务类型选模型, 不固定角色, B/C 两票永远异构。

| 任务类型 | 首选 |
|---------|------|
| 常驻主控（调度/实现） | deepseek |
| 大范围审查 / 长 diff | kimi |
| 安全/合规/边界核查 | chatgpt |
| 疑难 bug | kimi + chatgpt 各自诊断 |
| 主控降级接管 | kimi 或 chatgpt |

【最低约束】
- 路由不得由模型自我判定: 用代码化分类器或人工初始标签; 多标签任务按最高风险标签优先
- 置信度未校准前仅作排序字段, 不作自动放行依据

## 2. 流水线（意图）

```
反馈仅收集 → 人工筛选 → 工单(编号, 结构化字段, 脱敏) → 主控定级处理
主控: 进场读约定 → 定级 → L3脚本/L2单干/L1实现+验收/L0交叉验证闸
L0 闸: 盲审(隔离) → 结构化输出 → 争议反驳 → 证据裁决 → 仍争议才人工 → 双环境发布
沉淀: 根因账本(ground truth) + 可审计决策日志 + 判例
```

【最低约束】L0-L3 定级必须服从 AGENTS.md 的 red/yellow/green:
- red 面任务 → 无论标几级, 恒禁先问老板
- 部署/数据库/生产写 → 人工授权, 不因"有闸"自跑

## 3. 交叉验证协议

【意图】两轮制（盲审+反驳）+ 投票 + 证据闸门。

【最低约束】裁决优先级表（消除"投票 vs 证据"冲突）:
```
1. 确定性检查失败 (check/测试/构建)  → 一律阻断, 模型一致通过也无权覆盖
2. 裁决链顺序固定: 盲审 → 争议反驳 → 证据裁决 → 仍争议才人工
   反驳环节只澄清误解/补证据, 不得因反驳自动放行;
   反驳后仍需证据裁决定案, 人工只在证据裁决后仍分歧时介入
3. B/C 投票:  都过→过 · 都拒→打回 · 证据裁决后仍分歧→人工
4. 模型意见不能单独打回无风险改动 (仅达严重级别的可复现问题才触发打回)
5. 人工终审: 争议/高风险事项
```
- 每次 L0 创建不可变输入快照（git commit/hash）
- B/C 在独立只读 worktree 审查同一快照, 互不可见, 防锚定
- 意见必须结构化: 类型/位置/复现/证据/影响/置信度
- **B/C 原始审查输出不可变归档**（与输入快照同批 commit）:
  A 不得改写/删减/合并后再存, 归档与决策日志分离
- 争议清单由归档的原始输出生成, 保证 A 无法通过遗漏或改写影响裁决

## 4. 权限模型

【意图】分层: 数据/工具/操作/网络。

【最低约束】
- 工具白名单（具体清单, 非黑名单）: 子 agent 仅 check/cat/grep/测试等只读; 写操作仅主控
- 子 agent 工作区 = 独立只读副本, 无生产凭据, 无网络出口到云平台
- 关键操作（部署/库写/生产写）人工确认, 高风险变更带复核标记
- 主控也受限: red 面/部署/数据库不可逆 = 恒禁先问老板（AGENTS.md 铁律）

## 5. 降级策略

【意图】任一模型故障流水线不瘫, 安全类宁停勿猜。

【最低约束】
- 降级绑定**风险类别**而非"模型可用": 安全/权限/生产数据/发布类统一 fail-closed
- 普通 L0 缺一票: 降级单票+标注; 安全 L0 缺票: 阻塞
- 阻塞必须有: 通知（herdr notification）+ 超时 + 升级路径（维护者不可达时的处理）
- 主控切换前: 状态快照 + 交接文件（当前任务/探索结论/未决决策）, 防止上下文重建歧义
- 主控上下文接近上限: 主动归档/摘要, 不硬撑

## 6. 自迭代与决策日志

【意图】知识沉淀可追溯、可回滚、防幻觉固化。

【最低约束】
- 决策日志: append-only + 每条含操作者身份 + 输入快照 hash + 工具原始输出引用
- 日志覆盖: 原始审查输出归档引用 + 人工授权记录 + **覆盖/推翻原因**（谁覆盖了谁, 为什么）
- 外部验证锚点: 结论必须经 测试/lint/人工/线上结果 之一验证才能标"已验证"
- 检索默认只返回 适用+已验证+未过期 条目; 未验证内容仅作标注的参考假设
- 根因账本 = ground truth: 写入权限明确（人工或经人工批准的自动项）, 决策日志引用之
- 知识库与版本控制绑定, 可 diff 可回滚; 定期盘点（频率与责任人明确）列待验证/已失效
- 验收含对抗项: 篡改/遗漏检测（归档 hash 校验、日志完整性检查）

## 7. 人工筛选工单（可持续设计）

【意图】反馈仅收集, 人工筛选后建单, 外部输入永不直接进模型。

【最低约束】
- 工单结构化字段: 编号/类型/优先级/描述(脱敏副本)/原始证据(只读保存, 模型不可见)
- 用户内容标记为不可信数据, 与系统指令/验收标准/执行动作分离
- 模型只读清洗后副本（字段化+脱敏）, 附件/链接不直通模型
- 紧急直通通道: 严重线上 bug 走直通 L0, 不等常规筛选节奏
- 人工负载设计: 批量处理节奏 + 优先级定义 + 未处理告警（防静默积压）
- 维护者不可达: 工单积压升级机制, 不自动放行

## 8. 发布路径

【意图】测试→生产逐级验证, 提审人工。

【最低约束】环境跳数明确并每跳定义验收+授权:
```
开发 → 测试(自动化验收) → 体验版(人工冒烟) → 提审(人工, 材料由主控准备+清单核对) → 灰度 → 全量
```
- 提审材料 = 主控准备 + 清单核对（隐私协议/类目/内容安全）, 人工终审
- 回滚预案在发布前就位

## 9. 落地阶段（验收含对抗性测试）

| 阶段 | 意图 | 验收（含非正常路径） |
|------|------|---------------------|
| P1 | 三模型接入+面板+骨架+日志模板 | 三模型可路由; 路由不由模型自判 |
| P2 | 白名单权限+交叉验证 SOP+编排 | 跑通 L0 正常路径 **且** 对抗性测试: 越权写/任务误分类/输出冲突/结果截断/中途失联/重复执行/注入工单/授权过期/归档篡改/意见遗漏 |
| P3 | 反馈收集+人工筛选工单+双环境发布 | 工单进流水线; 注入工单被隔离; 紧急通道可用 |
| P4 | 决策日志盘点+判例闭环 | 未验证条目不参与检索; 盘点任务有明确频率与责任人 |
