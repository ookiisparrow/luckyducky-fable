# 后台360工作站 · 架构规范（顶层设计单源）

> **这是什么**：后台360工作站(自建客服+360+私域沉淀体系)的**顶层设计思维与架构铁律**。**核心思维＝组件化 / 模块化**：系统 = 一组可独立开关、可组件化接入、彼此解耦的**功能板块(模块)**。子项目现已建成挂起（状态见 `README.md`），本册留作按需重启时的设计法源。
> **provenance**：用户 2026-06-30 确定自建后追加的架构规范。调研/决策史见 `史料「客服选型研究.md」`。

## 0. 一句话顶层设计

> **后台360工作站 = 一组自包含的「功能板块(模块)」**。每个板块管好自己的数据/逻辑/UI，对外**只暴露一个声明式接口**；板块之间**不直接耦合**，要协作就经**统一接口/注册表**；每个板块**可单独开关**；新板块**组件化接入、核心零改**。

## 1. 五条架构铁律

### 铁律一：模块化为单位（不是散落改动）
- 系统按**功能板块**切分：每板块 = 自己的 cloud actions + admin 组件/页 + 自己的集合(如有)。
- **每个施工批次产出一个自包含模块**，而非横跨多处的散落 patch。模块边界 = 批次边界。

### 铁律二：板块间解耦（禁直接互 import）
- 板块之间**禁止直接 `import` 对方内部**。A 板块要用 B 的能力，只能经**统一接口/注册表**，不得伸手进 B 的实现。
- 沿用项目既有「**平台接缝单点**」思想(根因#12)：耦合点收口到一处、不散落。

### 铁律三：耦合处收束为通用接口（provider 模式）
- 必要的协作**收束为声明式通用接口**。典型＝**360 聚合用 provider 接口**：
  - `getCustomer360` = **orchestrator(编排器)**，本身不认识任何具体板块。
  - 每个 360 板块实现统一接口 **`CustomerPanelProvider { key, label, enabled, order, fetch(openid) → panelData }`**，注册到 **provider registry**。
  - 编排器只遍历 registry 里 `enabled` 的 provider、调 `fetch`、组装结果。**加/删/改一个 360 面板 ⇒ 只动那个 provider，不碰编排器。**
- admin 前端同构：板块 = 组件，经**板块注册表**挂载；页面壳只渲染注册表里的板块，不硬编码板块列表。

### 铁律四：功能板块可单独开关（feature toggle）
- 一个**模块注册表 + feature flag**(config 驱动)。每板块声明 `enabled`；关掉即**不挂载前端 / 不进 360 聚合 / 不暴露入口**。
- 价值：**灰度上线**、**出问题单独关**(不波及其它板块)。

### 铁律五：新板块组件化接入（开放-封闭）
- 新增板块 = ① 实现接口(provider / admin 组件) ② 注册到注册表 ③ 配 feature flag。
- **核心(编排器 / 页面壳 / 路由)零改动**——对扩展开放、对修改封闭。

## 1.5 信任边界铁律（360 读 = 新越权面）

- **360 聚合 = 本项目第一个「非本人批量读他人全量数据」的口子**（订单+物流+PII+学习轨迹）；旧审计范式跳 `^(get|list)` 恰不覆盖这类「读他人全貌」——故**审计(谁查了谁) + RBAC(谁有资格查) 与数据暴露同生、不滞后**。已落机器守卫：`rw-cs-360-read-audited`（读全貌破例留痕）+ `rw-cs-360-rbac-gated`（坐席能力位闸）。
- **告知同意**（数据共享给第三方坐席/外包看）义务随「第三方访问」出现才触发——商户本人查看不触发（数据控制者·现有隐私政策覆盖）。承面 A/C 按需重启时同批立，勿提前守空气（2026-06-30 防过度工程裁决）。

## 2. 与现有架构的衔接（不另起炉灶）

复用现有 admin 壳 + adminApi `ACTIONS` 注册表（本就是注册式接入雏形）、kit 收口纪律（云原语只在 kit）、`getCustomer360` 编排器 provider 模式——新板块沿同一范式延伸，不另造机制。

## 3. 反过度工程边界（防把「模块化」做成摆设）

板块粒度 = 一个有意义的功能单元，不是把一个函数也包成"模块"；provider 接口只在真有多个同类板块要聚合时用；feature flag 只给会独立开关的板块。**但信任边界守卫(§1.5)不算过度**——守的是真实存在的新越权面，防过度防的是投机抽象、不是真风险的防护。
