## 四、关键发现（踩坑记录）

### 4.1 HTTP 端点缺失
- yaliceshi 环境的 **HTTP 访问服务为空**，adminApi 无 HTTP 触发（触发器：无）
- 所有 `*.service.tcloudbase.com` 路径返回 `INVALID_PATH`
- **影响**：无法用 k6/wrk/ab 打标准 HTTP；测试改用 node-sdk `callFunction` 直调（方案 A）
- **注意**：测试环境云端函数名是 `adminApi`（旧名），生产是 `adminApiV2`（路径 /adminv2）——部署时别搞混

### 4.2 代理/TUN 网络问题
- 微信开发者工具走代理 `127.0.0.1:7890`（FlClash）；代理关闭时工具 cloudbase API 报 `ECONNREFUSED`
- 代理 TUN 隧道（utun4，198.18.0.x）到腾讯云**不稳定**：node-sdk 高并发会 `ETIMEDOUT`
- **策略**：压测时关代理（直连稳定）；工具查询/管理时开代理

### 4.3 环境限流阈值（核心结论）
- yaliceshi 的 API 限流约 **350 TPS**（实测：10 并发 TPS=88 → 50 并发 TPS=323 → 之后不再涨）
- 超限返回 `EXCEED_RATELIMIT`，**是环境配额，非产品缺陷**
- 日常负载（≤10 并发）实测：P95≈130ms、0 错误

### 4.4 压测数据残留
- loadtest 中断会残留 `_loadtest` 数据（下次 count 叠加，如 3707≠2000）
- 跑前确认清理：`loadtest` 集合 `where({_loadtest:true}).remove()`（remove 不支持 limit）

## 五·补2、生产并发验证记录（2026-08-15·经赵大爷批准）

**目的**：验证生产环境高并发下支付回调一致性（AI 代码最大风险点：并发下的钱/库存）。

**方法**：生产库造 50 个 `__prodtst_` 测试订单（30 匹配/10 欠付/10 多付，金额 0.01 元，带 `__prodtest__` 标记）+ 测试库存 50 件 → `tcb fn invoke payCallback` 10 并发 × 150 次回调（每单 3 次验幂等）→ 验证 → 清理。

**结果（全部通过）**：
- 状态机：30 paid + 20 payment_exception，0 悬空
- 金额校验：underpaid 10 + overpaid 10，无错判
- 幂等：无重复入账
- 库存：50 → 70（+20 回补）精确，无超卖
- 150 次调用 0 失败；测试数据清理后 0 残留

**关键经验**：
- 微信开发者工具写生产库需用户在工具内确认（pending + taskId 轮询）
- 工具登录过期会导致写操作失败（需重新扫码）
- `tcb fn invoke` 可直调生产云函数（无 OPENID = 可信服务端调用）

## 五·补3、生产环境 HTTP 性能压测（2026-08-15·赵大爷批准猛打）

**对象**：`POST /admin` ping（免鉴权探活）· ab + node fetch（keep-alive）· 每档 15s

| 并发 | TPS | P50 | P95 | P99 | 错误率 |
|---|---|---|---|---|---|
| 10 | 194 | 50ms | 61ms | 79ms | 0% |
| 50 | 567 | 49ms | 68ms | 298ms | 47.9%（429） |
| 100 | 463 | 56ms | 85ms | 196ms | 70.3%（429） |
| 200 | 547 | 67ms | 120ms | 512ms | 67.9%（429） |

**结论**：
- 生产环境稳定承载 **~500 TPS**（限流阈值，超出优雅 429），P50 ≈ 50ms
- 对比测试环境（~350 TPS / 95ms），生产吞吐更高、响应更快（标准版套餐）
- 关键坑：ab 默认无 keep-alive 时 TPS 仅 25（连接瓶颈假象），加 `-k` 后真实吞吐 500+
- 压测对象为 ping（平台吞吐）；真实业务接口（带鉴权+DB）会略慢，正常负载无虞
