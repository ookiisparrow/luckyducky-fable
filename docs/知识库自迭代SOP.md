# 知识库自迭代 SOP（P4）

> 定稿方案 §6「可审计决策日志」落地。目标：知识沉淀可追溯、可回滚、防幻觉固化，系统随运行变强。

## 一、闭环流程

```
每轮交叉验证/决策完成 → 写 .agents/knowledge/decisions.md (append-only)
→ 每周运行盘点: npm run audit:knowledge
→ 盘点输出: 待验证/已失效条目 + 统计
→ 人工审计:
    重大教训 → 经人工确认入 docs/判例索引.json (nofix 类, 防重提)
    过时条目 → 标记「已失效」(不删除, 保留历史)
    未验证条目 → 禁止作权威依据 (检索跳过)
```

## 二、决策日志纪律

1. **append-only**：只追加, 不修改历史条目。每条一个 entry, git 可 diff 可回滚。
2. **必填字段**：时间/操作者/输入快照hash/结论/依据/适用条件/失效条件/置信度/来源/验证状态/覆盖原因。
3. **验证状态**：`已验证[测试|lint|人工|线上]` / `待验证` / `已失效`。
4. **未验证条目 = 参考假设**：任何 agent 不得以未验证条目作权威依据（防幻觉固化——双票共识）。

## 三、判例索引（docs/判例索引.json）

- 四类：decision / rootcause / debuglog / **nofix（人工精选·可手工增补·不计数核）**
- 流水线教训沉淀到 nofix 类：`{id, kind:"nofix", title, keywords, source, status, note}`
- 守卫 precedent-index-synced 保护前三类计数与账本一致——改动前三类须同步账本, nofix 可直接加

## 四、指标（可选, 用于优化模型路由）

- 交叉验证发现率：每轮 B/C 发现问题数（严重/中等/轻微）
- A 漏检率：B/C 发现而 A 未自检出的比例
- 双票交集率：交集问题 / 总问题（高 = 模型共识稳定）
- 数据来源：.agents/archives/*.md 审查归档（已含结构化输出）

## 五、运行方式

```bash
npm run audit:knowledge   # 盘点（零模型成本, 建议每周一次, 可挂 cron）
```
