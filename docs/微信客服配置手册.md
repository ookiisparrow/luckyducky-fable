## 6. 排障手册（真机踩过的坑，按现象查）

**现象：点「完成」报「请填写带 http 或 https 协议头的合法 URL」**
→ URL 框开头/结尾混进了空格（开头空格会让它判定不是 https 开头）。清空手动重输、确认无空格。

**坑②｜现象：报「openapi回调地址请求不通过」（URL 格式已对）**
→ 微信真发了 echostr 但函数验不过。99% 是**表单里的 Token/AESKey 与 env 不是同一个字符**（大写 I vs 小写 l vs 0/O 抄串）。**定位法**：用 §7 的脚本本地构造一个真 echostr 请求打线上，看回的是不是明文——回空＝验签/解密对不上。**根治**：用无歧义字符重新生成两个值，表单 + env 从同一份复制粘贴。

**坑③｜现象：echostr 过了、发消息后日志 `[kf] sync errcode:95012`、无回复**
→ `95012 = 无权限调用接口`。`WXKF_SECRET` 填错了——用成了**企业微信自建应用的 Secret**，要用**微信客服「开发配置」页的 Secret**。两者 token 权限范围不同，自建应用 token 调不了 `kf/sync_msg`。改 env 后若旧 token 已缓存，删 `kfState` 的 `_id="token"` 记录强制重取。（实测：微信客服 secret 不卡可信IP，云函数任意出口 IP 可调；自建应用 secret 才要配可信IP，会报 60020。）

**坑④｜现象：sync 成功 `errcode:0` 但日志全是 `[kf] dup-skip`、不回复**
→ `kfState` 集合没建。去重靠往 `kfState` 写「已读痕」，集合不存在→写失败→每条消息被当「已处理过」跳过。建 `kfState`、`kfIdentity` 两集合即可。

**现象：一次冒出好几个气泡**
→ 多为**历史积压一次性回**（之前失败期间发的消息攒着，首次成功 sync 全回了）。去重生效后同一条不会再重复回，发一条新消息验证「一条一回」即可。

**转人工模型（2026-07-02 起·承面C 自建工作台版·调试日志 AC）**
→ 转人工**不再调平台 `service_state/trans`**：会话入自建 `csSession` 待接队列（`/agent` 坐席工作台认领/回复/结束）+ 发文字确认；**平台会话恒智能助手态(1)**——坐席回复走 `send_msg` API、仅 state=1 可发，曾转 3（原生接待台模式）致坐席发送全被 **95018** 拒。bot 不抢话由**我方 csSession 态**判（pending/active/escalated 静默·closed 恢复）。**企业微信原生接待台自此退出人工链路**（历史路 A/B 取舍与 48002 排障见 git 2026-07-02 前版本·AB 拍板 A 已被取代）。⚠️ 若在接待台手动接入过某会话（state 3），坐席对它发消息仍 95018——在接待台结束该会话即恢复。

**现象：进会话欢迎气泡发不出 `[LD_ALERT] SENDMSG_FAILED errcode:40058`**
→ `40058 = 不合法参数`。常见两因：① 进会话事件的 `external_userid` 在 `event` 子对象、取顶层取成空 touser（已在代码修，抽 `extUserId` 兜两种 wire 形状）；② 缺 `WXKF_MINIAPP_APPID`/`WXKF_THUMB_MEDIA_ID` 致小程序卡片参数不全。

**坑⑤｜现象：发消息 bot 不回（`[LD_ALERT] SENDMSG_FAILED errcode:95018`，或日志 `[kf] service-state {state:3}` + `assistant-gate {gate:'skip'}`）（调试日志 AB）**
→ **先分清 bot 是真坏还是会话在人工态**。微信客服 `send_msg` 由 API 发**只在 `service_state=1`（智能助手）允许**；顾客一旦点过「找人工」→会话转 state 3（人工接待·聊天里显示「已接入人工服务」），此后该会话所有消息都归人工，bot 发不出（旧代码硬发→95018）或正确避让（现代码 `skip`）。**最常见误判**：拿一条**被转过人工的会话**测 bot，看它不回就以为 bot 全坏——其实换条干净新会话 bot 正常（欢迎菜单/关键词都回）。
→ **定位法**：看日志 `[kf] service-state {state}`——`0`（新会话·未处理）/`1`（智能助手）＝bot 会回；`3`（人工）/`2`（排队）/`4`（已结束）＝bot 让位、这条得人工在接待台回或起新会话。**验 bot 是否正常：用一个从没找过人工的干净微信发消息**（→ state 0 → bot 回）。
→ **代码侧（已上）**：`kfCallback` 回复前经 `kit/wecom.ts` 的 `ensureSmartAssistant`（读 `service_state/get`→**只接管 0 新会话[trans→1]·1 直发·2/3/4 让位 skip**——平台不允许 2→1、4→1[4→1 报 95013]，只硬试新会话免告警噪声）。日志 `assistant-gate {gate:'proceed'}` 即接管成功。（转 state 1 **不需要** servicer_userid，转 3 才需。）
→ **运营**：确认「通过API管理微信客服账号」已把该账号托管给自建应用（企业微信后台 → 微信客服 → 企业内部开发·本项目 Lucky Ducky 已托管）；「找人工」转人工后须有坐席在**自建 `/agent` 工作台**认领应答（原生接待台已退出人工链路·见上方转人工模型），否则顾客卡人工态无回复——无人力则考虑改「找人工」话术不真转人工（`dispatch.ts` 转人工分支）。

**通用：看链路日志**
`npx tcb fn log kfCallback -e cloudbase-d4gcssqbv06865479`，盯 `[kf]` 全链路（onEvent / cursor-read / sync{errcode,msgs,nc} / handle / **assistant-gate** / sent / dup-skip）+ `[LD_ALERT]` 告警码。

## 9. TypeSafe / Jev 体验分流（正式默认关）

顾客入口还是 **我 → 联系客服**，进的还是同一条企微会话。Jev **不**挂在小程序点按钮那一下，而是挂在已经进线的自由文本分流上（`dispatch.ts`，转人工之前）。

| 环境 | 行为 |
|---|---|
| **正式 / 闸关** | 旧关键词 + 根菜单，完全不打 TypeSafe |
| **体验 / 开发** | 闸开才问 Jev；问挂了仍走旧关键词/根菜单（fail-open） |
| 打中「物流/激活码/退款…」 | **仍走旧关键词菜单**（Jev 只记一笔非密钥证据） |
| 没打中关键词、Jev 回了科室 | 按科室弹对应菜单：billing→售后 / technical→课程 / sales→教程 |

企微 HTTP 回调**拿不到**小程序 `envVersion`。本仓又只有一个生产云环境，所以体验闸 = 运行时 `JEV_CS_ROUTE=1`（云函数 env 或 `secureConfig/typesafe`）。若进程里能读到 `WX_ENV_VERSION`/`TCB_ENV_VERSION`=`develop`/`trial` 也会开；字面 `release` 则强制关。

**怎么把盒里的密钥填进云（人工·本批不部署）**

1. 只在操作机打开 `/home/box/.config/typesafe/cs.env`，里面有 `TYPESAFE_API_KEY`。不要把这一行贴进 PR、聊天、截图、日志。
2. 云开发控制台 → 云函数 `kfCallback` → 环境变量：
   - `TYPESAFE_API_KEY` = 盒里那个值
   - `JEV_CS_ROUTE` = `1`（只在要取证的那几天开）
3. 重新部署 `kfCallback`（改 env 必须部署才进进程）。部署是人工授权，别让代理自己跑。
4. 用**体验版**小程序：我 → 联系客服 → 发一条真消息。云日志应出现一行 `[kf] jev`，带 `model`（探针约 `jev-1.13.0`）、`urgency`、`department`，**没有**密钥、没有 Authorization。
5. 取证完：删掉或把 `JEV_CS_ROUTE` 改成 `0` 再部署；去 TypeSafe 控制台轮换密钥，盒文件和云函数 env 一起换。

Jev 挂了（超时/4xx/解析失败/没填密钥）顾客仍看到旧菜单，不会卡死。出网目标是官方 `https://api.typesafe.ai/v1/systemone`，不走 OpenRouter/Cloudflare。
