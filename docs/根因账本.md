# 根因账本

> 反复咬人的病根。每条写清病史、本质、规矩和现在靠什么守。
> 治理流水线见 `CLAUDE.md`「干活流水线」。编号全库在引用（代码注释「根因#N」、守卫 `roots`），**只增不改号**。
> 某条病根现在有哪几条守卫：`grep -n "'#N'" scripts/check-structure.mjs`（看 `roots` 字段），本文不手抄守卫清单。各条的完整病史用 `git log -p -- docs/根因账本.md` 查。

## 病根

### 1. 并发「先查后写」、一次性副作用不幂等
- **病史**：退款审批曾无原子抢占，并发可致同一笔订单双倍退款。
- **本质**：检查和写入分两步做，并发窗口必然存在。
- **规矩**：确定性 `_id`（撞 id 即已写、天然幂等）；抢占一律条件更新 `transition()`；一次性副作用绑首次状态转移。
- **靠什么守**：机器守

### 2. 状态转移散写、副作用反查状态集窄化
- **病史**：退货权反查曾写死 `status:'paid'`，订单流转到 shipped 后静默断链。
- **本质**：状态机没有单一权威表，每处转移各自背规则。
- **规矩**：状态写入只走 `transition()` 合法流转表；调用方用 `ORDER_STATUS` 常量，写错名编译失败。
- **靠什么守**：机器守 + 类型系统

### 3. 信任边界靠每个函数自觉
- **病史**：支付回调曾可被客户端伪造成「支付成功」；seed 函数曾无鉴权。
- **本质**：安检靠每个函数自觉，越「不像业务」的函数越容易忘。
- **规矩**：kit gate fail-closed 缺省（`withOpenId`/`withAdminGate`/回调见 OPENID 即拒），不过闸写不了库。
- **靠什么守**：机器守

### 4. 金额浮点靠手工纪律
- **病史**：全库价格曾以元存储，换算全凭人记。
- **本质**：金额安全依赖人记得换算，类型系统不设防。
- **规矩**：`Fen` 品牌类型，全链「分」整数，元只在展示层，边界收元转分一次。
- **靠什么守**：机器守 + 类型系统

### 5. 样板复制即漂移
- **病史**：支付/退款回调两份实现重复约七成、各自漂移。
- **本质**：复制是默认选项，而复制必然漂移。
- **规矩**：共享内核进 kit/shared；小程序进不了 shared 的常量落副本，由守卫核两边一致。
- **靠什么守**：机器守

### 6. 演示回退双路径泄漏
- **病史**：旧线演示回退曾把云端拒单吞成「已成功」。
- **本质**：无云回退与真路径并存却无统一契约。
- **规矩**：新线小程序只经 lib 层读云、没有本地样例回退，病根所在的双路径已不存在。
- **靠什么守**：机器守（`rw-mp-cloud-only`）

### 7. 固定 limit，规模即挤出
- **病史**：多个列表固定 limit 200，数据一多旧单被静默挤出后台。
- **本质**：「先写个数字够用」没有退出机制。
- **规矩**：列表统一 cursor/limit 分页契约，禁固定 limit。
- **靠什么守**：机器守

### 8. 验证样本失真——「E2E 过了」≠「真的能用」
- **病史**：小尺寸测试图和内存桩让 E2E 全绿，真实照片一上线就失败。
- **本质**：验证样本离真实越远，「通过」越不可信；AI 自报通过同理。
- **规矩**：真实尺寸样本、完整请求形状走到最后一步、真机才算数；PR 里声称验过须附证据。
- **靠什么守**：部分机器守 + 靠人（`CLAUDE.md` `[靠人:#8]`）

### 9. git 外资产无正册
- **病史**：八件控制台资产只散记在日志，误删即支付瘫痪。
- **本质**：git 外的配置没有版本管理，灾难恢复靠记忆。
- **规矩**：`console-assets/` 正册化，变更先 repo 后控制台。
- **靠什么守**：机器守 + 靠人对照控制台

### 10. 工具实例状态不可信
- **病史**：开发者工具 build 与自动化互踩后，RPC 不回包、白屏等假象反复出现。
- **本质**：有状态的共享工具实例，表象不可信。
- **规矩**：跑 build 前停自动化；遇怪象先 `cli quit` 重启再排查。
- **靠什么守**：靠人（`CLAUDE.md` `[靠人:#10]`）

### 11. 文档职责渗漏
- **病史**：CLAUDE.md 曾涨到 314 行；文档里的名字、数字、守卫名多处过时。
- **本质**：文档手抄事实就会漂移，没有容量规则就会膨胀。
- **规矩**：事实以代码为准不手抄；过期直接删，git 即归档层。见 `CLAUDE.md` 流水线第 1 步。
- **靠什么守**：机器只守模块正册同步；其余靠 review

### 12. 平台规则外部风险
- **病史**：云调用支付曾被平台整条封死；退款单号曾带中文被微信拒收。
- **本质**：平台规则会单方变化，我方传出参数也须合平台契约。
- **规矩**：平台接缝收到 kit 单点（`callFlow` 等）；传出标识符在接缝处规整。
- **靠什么守**：机器守

### 13. 无频控，认证/写入端点可被爆破或滥用穿透
- **病史**：后台口令端点曾公网裸奔、无重试限制、快哈希存储。
- **本质**：没有限速，门锁再硬也挡不住无限次尝试。
- **规矩**：认证与高频写端点必过频控；口令 salt+scrypt KDF。
- **靠什么守**：机器守

### 14. 失败静默化——吞错 / 伪成功 / 告警不进人眼
- **病史**：客服机器人失败只写进没人看的日志；坐席发送失败却回「成功」。
- **本质**：失败点的缺省行为是静默。
- **规矩**：动作类失败必经 `observe.alert` 单出口；fail-soft 只改返回语义，不抹可观测性；失败≠空态。
- **靠什么守**：机器守；另有大量「装成空」由审查发现，靠 review

### 15. 加载链路冗余云调用——跨页共享的静态目录数据无会话缓存收口
- **病史**：多个页面绕过缓存直调云端，重复拉同一份目录，单次往返 0.7–1.4s。
- **本质**：已有的会话缓存范式没有被收口，新页面各自重犯。
- **规矩**：跨页只读目录数据经 `lib/catalog.ts`/`lib/courses.ts` 缓存取，页面不直连 api 层。
- **靠什么守**：部分机器守（图片预算）；缓存收口靠 review

### 16. 守卫绑定漂移——扫描面/指针指着死目标，空样本＝绿
- **病史**：残留 worktree 被守卫当活代码扫；两条守卫同 id 重复注册，坏版本跑了 6 天。
- **本质**：守卫与现实之间的绑定（扫描路径、指针）会漂移，且空样本看起来是绿的。
- **规矩**：扫描面统一排除；守卫 id 重复注册即红；守卫少而准，绑定才看得过来。
- **靠什么守**：引擎自检 `assertNoDuplicateIds` + 靠 review

### 17. 快照外无传感器——持续性义务无机器建模，恶化不发信号
- **病史**：package-lock 里揣着 639 个死包无人察觉。
- **本质**：快照断言只管「此刻违没违例」，不管趋势，膨胀每一步都不违例。
- **规矩**：依赖锁走基线棘轮；死导出、幽灵依赖、孤儿资产零容忍。
- **靠什么守**：机器守
