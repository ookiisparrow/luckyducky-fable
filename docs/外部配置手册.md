# 外部配置手册

> 代码之外、要在各平台后台操作的配置：在哪、怎么做、怎么验。**状态不在这里记**：上线前还没做完的项在 GitHub Issue #371。
> 凭证轮换与故障处置见 `docs/运维手册.md`；支付工作流、库权限、复合索引、VOD 的资产正册与重建手册见 `console-assets/`。本文只写字段名，不写值。

## 一、小程序后台（mp.weixin.qq.com，AppID `wxcbd2fb68b81bcfb1`）

- **版本上传、提审、发布**：微信开发者工具打开 `rewrite/mp` 点「上传」，或命令行 `wechatide -c ldrw-cli upload --project rewrite/mp --upload-version <版本号> --desc "<说明>"`（过部署闸，整行敲）。「我」页日期与通道由提交钩子/预览/发布脚本自动戳，不用手改。之后在后台「版本管理」提交审核、审核通过后发布（建议先分阶段 25%）。提审和发布只能在网页做。
- **用户隐私保护指引**：「设置 → 服务内容声明 → 用户隐私保护指引」，勾选的信息类型（手机号、地址、相册等）与小程序实际采集一致。代码侧对应 `rewrite/mp/pages/consent`。不一致可能被下架。
- **内容安全接口**：「开发 → 开发管理 → 接口设置」确认已启用。没开通时带图评价、头像、打卡照片会一律被拒（fail-closed）。
- **快递100 插件**：「第三方设置 → 插件管理」添加「快递查询」（appid `wx6885acbedba59c14`，版本以 `rewrite/mp/app.json` 为准）。没订阅时「查看物流」打不开，会退回复制运单号。
- **扫普通链接二维码打开小程序**：「开发管理 → 扫普通链接二维码打开小程序」添加已备案域名、把后台给的校验文件传到该域名根目录、配置规则把前缀绑到 welcome 页，用真机扫一张测试码验证。印刷在材料包上的激活码就是这种普通链接（`https://<域名>/q/<码>`）。
- **明文 Scheme 拉起小程序**：「隐私与安全」里开启。内容站 `/q` 落地页的「一键拉起」按钮依赖它。
- **downloadFile 合法域名**：「开发管理 → 服务器域名 → downloadFile 合法域名」，必须包含 `https://cloudbase-d4gcssqbv06865479-1440904924.tcloudbaseapp.com`（品牌字体从托管 `/fonts/` 下载，见 `rewrite/mp/utils/brandFont.ts` 的 `FONT_HOST`）。刻意不用 `www.luckyducky.cn`：手机微信对它的证书 CA 更挑剔。换托管域名时先改 `FONT_HOST` 再进后台加域名（合法域名修改有额度）。完整名单以后台那一页为准。
- **官方监控三件套**：「开发管理 → 运维中心 / 性能监控」开启告警并绑定接收人微信。发布后才有数据。
- **getPhoneNumber 一键手机号**（可选）：需要企业/组织主体认证和接口额度确认；现在是手动输入。

## 二、云开发控制台（tcb.cloud.tencent.com，环境 `cloudbase-d4gcssqbv06865479`）

- **敏感凭证统一填在 admin `/config-checklist`**（写 `secureConfig` 集合，填即生效）。字段表与轮换步骤见 `docs/运维手册.md`「凭证轮换」。
- **首个超级管理员**：`adminApi` 环境变量 `ADMIN_BOOTSTRAP_KEY` 设一个足够长的保密串，首次用它登录 admin 建出超管后移除该变量（它就是超管口令，留着会在函数详情里明文显示）。`adminConfig/auth` 文档存在即已引导过；变量没删时 `/config-checklist` 会多出一行「应删除」。
- **微信支付商户 API 证书**（外部对账用）：商户平台 pay.weixin.qq.com「账户中心 → API 安全」取证书序列号和商户私钥，填 `/config-checklist` 的 wxpay 两项（私钥保留换行）。未配时每日对账静默跳过。
- **支付连接器、支付/退款工作流、商户号、`config/pay` 文档**：正册与 30 分钟重建手册见 `console-assets/01-支付退款工作流.md`。改工作流后必须点「发布」。
- **数据库集合与云存储权限**：期望档位见 `console-assets/02-库权限期望表.md`；一次列出全部 `tcb permission get collection -e cloudbase-d4gcssqbv06865479`，业务集合全部应为 adminonly，有偏差 `tcb permission set collection:<名> --level adminonly` 改回。
- **「没有 OPENID 就是可信服务端」靠控制台守住**：支付/退款回调、各定时器、`initDb`/`seedCourses` 判断「是不是服务端在调」只看调用上下文里有没有 OPENID（以 `rewrite/cloud/src/kit/gate.ts` 的 `isServerCall`、`withAdminGate` 为准）。小程序调用一定带 OPENID，会被拒；但下面这些入口调进来都不带 OPENID，会被当成服务端直接放行——回调能把订单翻成已付，`seedCourses` 能整份覆盖课程。逐项核对：
  1. **身份认证 → 登录方式**：匿名登录关闭，其他 Web 端登录方式（用户名密码、短信、邮箱、自定义登录等）也都不开。Web 端用户调云函数时上下文里没有小程序 OPENID；本项目的 admin、坐席台、官网都不用云开发 Web SDK（后台走 `adminApi` 的 HTTP 入口，自带口令鉴权），关了不影响业务。
  2. **HTTP 访问服务**：路由只应有 `adminApi`（路径以 `rewrite/admin/.env.production`、`rewrite/agent/.env.production` 为准）和 `kfCallback`（见 `console-assets/README.md`）。这两个函数自己鉴权（口令/会话、消息验签），不靠 OPENID；`payCallback`、`refundCallback`、定时器、`initDb`、`seedCourses` 等其余函数一条路由都不能有——HTTP 请求没有 OPENID。
  3. **访问管理 CAM**：能调用云函数或改函数配置的主账号、子账号，在函数眼里都是「服务端」（`tcb fn invoke`、`tccli scf Invoke`、控制台「测试」都不带 OPENID）。子账号按用途最小授权：VOD 子账号只授点播权限（它的密钥存在 `secureConfig/vod`，后台能读到），不给云开发/云函数权限。
  核对结果记在 Issue #371。
- **复合索引**：照 `console-assets/03-复合索引期望表.md` 在「数据库 → 索引管理」建，建完 `npm run db:check-indexes` 核对。
- **腾讯云点播 VOD**：开通、子账号、任务流、播放域名与防盗链的重建手册见 `console-assets/04-视频点播VOD.md`；四项凭证填 `/config-checklist`「视频点播 VOD」组。未配全时上传自动走云存储老路。
- **数据万象图片处理**（可选，默认关）：腾讯云数据万象控制台对云存储桶开通 → 想好参数串（如 `imageMogr2/thumbnail/750x/format/webp/quality/80`）→ **先真机验证**：手动拼到一个签名临时图 URL 后面（已有 `?` 用 `&`）确认能打开、签名不失效 → 再填 `app` 函数环境变量 `LD_IMAGE_PROC`。清空即关闭。

## 三、企业微信与微信客服

### 架构
顾客在微信客服会话里发消息 → 企业微信**自建应用 Lucky Ducky**（AgentId `1000002`）的「接收消息」回调 → `https://kf.luckyducky.cn/kfcallback` → 云函数 `kfCallback`：验签解密 → 拉消息 → `dispatch.ts` 分流（关键词菜单 / FAQ / 查订单 / 小程序卡片 / 转人工）。话术、关键词、FAQ 都在代码里（`rewrite/cloud/src/functions/cs/kfCallback/`），改完要重新部署 `kfCallback`。

**客服账号只经企业微信自建应用管理**。微信客服独立端 `kf.weixin.qq.com` 的「开发配置」回调已弃，**不要再配、不要来回切**：切换会换掉验签凭证模型，客服必断。

### 前置
1. 企业微信企业认证（企业 ID `wwda6861818cb50dd9`）。
2. 微信客服账号（open_kfid `wkXCYoNAAAytL3jmRHxxzb8sYLl2Kpcg`）；顾客入口二维码/链接在「客服账号」里拿。
3. 企业微信后台「微信客服 → 企业内部开发」显示「正通过自建应用 Lucky Ducky 管理此账号」。
4. 回调域名 `kf.luckyducky.cn`：已备案且与企业主体一致、CNAME 指向云开发 HTTP 访问服务、配 SSL（证书运维见 `ops/certs/README.md`）。
5. 小程序绑定微信开放平台（查订单的身份桥）：顾客用同一个微信登录过小程序，`kfCallback` 就能经 unionid 反查到 openid。「unionid 不在 users」最常见的原因是发消息的微信没登录过小程序。

### 凭证（写 `secureConfig/wxkf`，经 `/config-checklist` 填）
| 项 | 取自 |
|---|---|
| 调 API 的 Secret | 自建应用 Lucky Ducky 的 Secret（不是独立端「开发配置」页那个） |
| 回调 Token / EncodingAESKey | 自建应用 Lucky Ducky →「接收消息（已启用 API 接收）」表单，两边逐字一致 |
| AgentId、企业 ID、小程序卡片 AppID 与封面 media_id | 自建应用与小程序后台 |
| 可信 IP | 自建应用「企业可信IP」登记云函数固定出口 IP（见 `docs/运维手册.md`「凭证轮换」） |

**变更纪律**：先改库再在后台点保存（保存会立即触发 echostr 验签）；改 Secret 后清 `kfState` 的 `_id=token` 缓存；**动任何后台配置后必发一条测试消息，验「一条一回」**。`kfHealthProbe` 每 30 分探令牌与可信 IP，但伪造回调这类问题测不出来，只能靠这条纪律兜。

生成无歧义 Token 与 AESKey（避开 I/l/O/0/1/o/i）：
```bash
node -e 'const c=require("crypto");const BAD=new Set(["I","l","O","0","1","o","i"]);const S="ABCDEFGHJKLMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz23456789".split("").filter(x=>!BAD.has(x));let t="";while(t.length<16)t+=S[c.randomBytes(1)[0]%S.length];let a;do{a="";while(a.length<43)a+=S[c.randomBytes(1)[0]%S.length]}while(Buffer.from(a+"=","base64").length!==32);console.log("Token =",t,"\nAESKey=",a)'
```

### 转人工与接待
转人工不调平台的会话转移接口：会话进自建 `csSession` 队列，坐席在自建 `/agent` 工作台认领、回复、结束。平台侧会话始终保持「智能助手」态（state 1），因为 `send_msg` 只在这个态下能发。**企业微信原生接待台不在人工链路里**，不要在那里手动接入会话，否则该会话坐席发送会被 `95018` 拒（在接待台结束该会话即恢复）。
接待人员：企业微信管理后台「微信客服 → 接待人员」添加成员；实际接待在 `/agent` 做。

### 排障
看链路日志 `npx tcb fn log kfCallback -e cloudbase-d4gcssqbv06865479`，盯 `[kf]` 各阶段（onEvent / sync / handle / assistant-gate / sent / dup-skip）与 `[LD_ALERT]`。

| 现象 | 原因与处置 |
|---|---|
| 后台填 URL 报「请填写带 http 或 https 协议头的合法 URL」 | URL 首尾混进空格，清空重输 |
| 「openapi回调地址请求不通过」 | echostr 验签没过：表单 Token/AESKey 与库里不是同一串（I/l/0/O 抄串）。用上面的脚本重新生成，两边从同一份粘贴。可按 WXBizMsgCrypt 用 AESKey 加密一段明文得 echostr、用 Token 算 msg_signature，GET 打线上 `/kfcallback` 看是否回明文来定位 |
| `FORGED_CALLBACK` | Token/AESKey 没对齐 |
| `95012` 无权限 | 用错了 Secret，必须是自建应用 Lucky Ducky 的；刚改过就清 token 缓存 |
| `60020` | 没配固定出口 IP 或没登记可信 IP。**不是换 Secret 的理由** |
| sync `errcode:0` 但全是 `dup-skip`、不回 | `kfState` / `kfIdentity` 集合没建（去重写不进去），建上即可 |
| 验签过但 `sync msgs:0` | 同步游标 stale：清 `kfState` 的 `cursor:<openKfId>` 那一条（别删 token/seen） |
| 一次冒出好几个气泡 | 失败期间积压的消息首次成功时一起回；再发一条新消息验「一条一回」 |
| bot 不回，日志 `service-state {state:3}` 或 `95018` | 该会话已被转过人工。用从没找过人工的干净微信测 bot；state 0/1 bot 会回，2/3/4 让位 |
| 欢迎气泡发不出 `40058` | 进会话事件的 external_userid 取错位置，或缺小程序卡片 AppID / 封面 media_id |

### Jev 体验分流（TypeSafe，正式默认关）
企微回调拿不到小程序 envVersion，而生产只有一个环境，所以体验闸是运行时开关 `JEV_CS_ROUTE=1`（云函数 env 或 `secureConfig/typesafe`；进程里 `WX_ENV_VERSION`/`TCB_ENV_VERSION` 为 develop/trial 也会开，为 release 强制关）。

| 状态 | 行为 |
|---|---|
| 闸关（正式） | 旧关键词 + 根菜单，完全不打 TypeSafe |
| 闸开 | 自由文本一律走 Jev + 话术库纯文本（快递/退款等旧关键词也不弹气泡）；菜单点选仍走原逻辑 |
| 闸开但 Jev/话术失败 | 发一句「请重试（或点找人工）」，不回旧菜单 |

密钥配法与轮换见 `docs/运维手册.md`「凭证轮换」。取证：用体验版小程序「我 → 联系客服」发几句，云日志应有 `[kf] jev` 行（含 orderStatus / emotionStatus / severity 等字段，无密钥、无 Authorization），顾客侧是口语短句；连聊第二句应往下走不重复。取证完把 `JEV_CS_ROUTE` 去掉或改 `0` 再部署，并轮换 TypeSafe 密钥。

## 四、域名、证书与群机器人

- **对外域名**：`www.luckyducky.cn`（官网 + `/admin` `/agent`）、`kf.luckyducky.cn`（客服回调）、`q.luckyducky.cn`（扫码落地页）、`vod.luckyducky.cn`（视频点播 CDN）。DNS 在腾讯 DNSPod。免费证书 3 个月一换且每次换 ID：续签、换绑、周检的脚本与参数见 `ops/certs/README.md`。
- **扫码域名**：生成 `/q/<激活码>` 链接用的域名必须已备案，且与小程序主体一致或有关联。
- **企微群机器人告警**：在企业微信内部群「添加群机器人」，复制 Webhook 地址，粘贴到 admin「设置」页 `alertWebhook`。`alertEvents` 控制哪些事件推送。
