## 0. 环境与铁律

- **唯一生产环境** `cloudbase-d4gcssqbv06865479`，小程序 AppID `wxcbd2fb68b81bcfb1`。本仓 `rewrite/` 的产物就是线上唯一版本（云函数 + `/admin` `/agent` + 根路径内容站），部署/建表/删表真实生效。
- **部署与 git 解耦**：`git push` 不改线上；每次部署都要老板点名授权，授权只覆盖点名的对象。
- **环境选择子**（真值 `scripts/lib/env.mjs`，`npm run env:resolve -- --target <x>` 查解析，不连云不要密钥）：

  | 选择子 | 用途 | 可写 | 对应分支 |
  |---|---|---|---|
  | `stub` | 内存桩，单测/断言 | 否 | — |
  | `test` | 测试云（压测/测部署/test-api） | 是（须显式 `--target test`） | `test` |
  | `prod-readonly` | 生产只读（巡检/断言） | 否 | `main` |

  生产写入只走 `deploy-fns` + `DEPLOY_ALLOWED`，没有 prod-write 选择子。
- **机器闸**：

  | 闸 | 拦什么 | 开锁 |
  |---|---|---|
  | pre-commit | `npm run check` 不过的提交 | 无（不 `--no-verify`） |
  | pre-commit 红区闸 | 红区路径的提交（名单 `scripts/lib/red-paths.mjs`） | 老板授权 `RED_ALLOWED=1` |
  | CI 红区闸（`.github/workflows/red-zone.yml`） | 触及红区路径的 PR（同一名单；补云端 agent 不走 pre-commit 的洞） | 老板审过后给 PR 打 `red-ok` 标签 |
  | `deploy-fns.mjs` 部署前提 | 不在 main、HEAD ≠ origin/main、工作区有改动时真部署 | 无（先 pull / 走 PR 合进 main / 收拾工作区） |
  | `scripts/guard-deploy.mjs` | 白名单以外的 tcb / wechatide 命令、任何 tccli、调了云 CLI 的运维脚本、跑 `deploy-fns.mjs`、`--include-secrets` | 人在确认框放行（`deploy-fns.mjs` 真部署另要 `DEPLOY_ALLOWED=1`） |
  | `.claude/settings.json` deny | AI 直调云端写工具（MCP 不经 Bash，deny 是唯一的闸）；只会明文打印密钥的命令（`tcb fn detail`、`tcb secrets get`、`tccli scf GetFunction`） | 不可解锁 |

- **guard-deploy 怎么判**：它是 Claude Code 的 PreToolUse hook，按白名单放行：`tcb`（含同一 CLI 的 `cloudbase` 入口）只放行确知只读、不打印密钥的子命令，其余一律弹确认——部署、改代码/配置、`fn invoke`（绕过身份闸直调函数）、`fn detail`（明文打印环境变量）、`db` 都在内；`wechatide` 同样只放行白名单工具。判定看「会不会读出或改动云端密钥与函数配置」，不看字面程序名：`tccli` 一律弹确认（`scf GetFunction` 会原样回显函数环境变量；`uvx`/`pipx run` 等前缀照认）；python、node 的脚本文件（含 `< 文件` 重定向）和 `-c`/`-e`/heredoc/管道喂进去的代码，调了云 CLI、腾讯云 SDK 或仓内凭证桥 `cloud-manager` 也弹——node 脚本只认真调用，注释里的字样不算；shell 脚本读出来逐行按同一套规则判；脚本读不到按弹处理；`npm run <名>`（run 前带 `-s` 等选项也算）按仓根 package.json 展开正文再判。白名单和判定细节以 `scripts/guard-deploy.mjs` 为准，用例表在 `scripts/check-structure.mjs` 的 deploy-gated 守卫与 `tests/scripts/r4-devgate-guard-deploy.test.js`。包装器（`env -u …`/`sudo`/`timeout`）、`npx` 这类 runner、循环/条件/命令替换里的命令都认得出。**部署一律直接敲 `tcb`，不要包成 npm script**：子包的 script hook 看不到，结构守卫也会拦含受管命令的 script。人在自己终端跑的命令不经此 hook。
- **前置**：`tcb` 已登录且默认环境为上面的 envId（`tcb env list` 核）；命令里显式带 `-e cloudbase-d4gcssqbv06865479` 最稳。本机 `http_proxy` 会挡 tcb 上传隧道（502），部署命令前缀 `env -u http_proxy -u https_proxy`。


## 1. 部署

### 1.1 云函数（名单以 `cloudbaserc.json` 为准）

```bash
npm run build:rw-cloud      # esbuild 打包到 rewrite/cloud/dist/<源码名>/（index.js + package.json + 按需 config.json）
tcb fn deploy <云端函数名> --dir rewrite/cloud/dist/<源码名> --force -e cloudbase-d4gcssqbv06865479
```

- **一次部署一个**：`tcb fn deploy A B` 只发第一个。
- **管理端只部署 `adminApi`**：源码目录、云端函数名、HTTP 入口都是它。线上不存在 `adminApiV2`，**不要部署它，更不要把在用的 `adminApi` 当旧名删掉**。其余函数源码名＝云端名。
- **带 `config.json` 的函数（`app`、`adminApi`）部署会弹「是否使用默认配置继续部署？(y/N)」**：非交互部署须 `echo y | tcb fn deploy …`，不回答默认 N、部署中断、云端仍是旧码（假部署）。回 y 后到云开发控制台该函数的「函数配置」页核内存/超时与 `cloudbaserc.json` 一致，没被默认配置改坏。
- **核对部署一律不用 `tcb fn detail`**：它连环境变量（含商户私钥）一起明文打印（§3.1）。
- **真生效验证**：`tcb fn list -e cloudbase-d4gcssqbv06865479` 看该函数修改时间是刚才（假部署不更新）；再按下方冒烟模板走一遍本批新行为，`tcb fn log <fn>` 里出现新代码的日志/告警特征即生效。
- **`app` 是单一函数、不可分部署**：部署它就是发布当前 checkout 的全部 app action。发之前拿**上次部署 app 的那个 `deploy-*` tag** 做 `git diff <该 tag> -- rewrite/cloud/src rewrite/shared/src`，看这次会一起带上哪些改动。
- **部署账本＝`deploy-*` 注释 tag**：`deploy-fns.mjs` 真部署只从「干净的、等于 origin/main 的 main」发，发完自动打 `deploy-<UTC时间>` tag（指向本次部署的提交，正文是 `{sha, deployed, functions}`）并推送，中途失败也记下已发的那几个。查：`git fetch --tags && git tag -l 'deploy-*'`，看正文 `git tag -n99 <tag>`。手敲 `tcb fn deploy` 单发的不进账本，下次 `deploy-fns --dry-run` 会把它报成待部署。第一个 tag 之前，账本退回仓根 `.deploy-manifest.json`（2026-09-29 的手工清单，已知落后线上）。

**顺序**（险级从低到高，每组冒烟过了再下一组）：
1. ops 组 `initDb`/`seedCourses`：部署成功即可，不在部署环节调用。
2. 定时器组 `cleanupEvents`→`kfHealthProbe`→`recallScan`→`closeExpiredOrders`→`inspect`→`billReconcile`→`feedbackNotify`：部署后核触发器仍挂（§5），可 `tcb fn invoke` 手跑一次看日志无错。
3. 客服 `kfCallback`：真发一条客服消息走通问答；顾客发图坐席台可看。（客服主动发送、媒体下载、激活码生成都在 `adminApi` 内，随它部署。）
4. 钱链最后 `payCallback`→`refundCallback`：真单最低额支付一笔看 pending→paid；退款真验一笔。
5. `app` 单列，先看上面的单一函数提醒。

**冒烟模板**：
```bash
tcb fn list -e cloudbase-d4gcssqbv06865479                              # 修改时间（别用 fn detail：打印环境变量）
tcb fn invoke inspect -e cloudbase-d4gcssqbv06865479                     # 应回 {green,red,...}
tcb fn log <函数名> -e cloudbase-d4gcssqbv06865479 | grep LD_ALERT        # 部署后盯告警行
```
`adminApi` 部署后打真端点错口令应回 `401 {ok:false,error:BAD_KEY}`；`ping` action 免鉴权应 200。

**先测后产**：`node scripts/deploy-test.mjs --target test` 发测试云冒烟，再授权发生产。

### 1.2 静态托管（admin `/admin`、agent `/agent`、site 根路径）

```bash
npm run build:rw-admin                                                   # → rewrite/admin/dist
tcb hosting delete admin --dir --yes -e cloudbase-d4gcssqbv06865479       # 先清空（--dir --dry-run 先预览命中范围）
```

- **先 `delete --dir` 再 deploy** 是硬纪律，不清空会残留旧 chunk。删目录**必须带 `--dir`**：不带会报「删除文件成功」却什么都没删。

- **入口哈希核验**（绕 CDN）：
  ```bash

  # 与 rewrite/admin/dist/index.html 里的入口名逐字比对，再 curl 该 chunk 看 200
  ```

## 2. 回滚

**没有数据迁移就没有数据回滚**：各版本共用同一套集合（确定性 `_id` + 幂等写），回滚只涉及代码层。

- **单函数**：`git checkout <好的commit> -- rewrite/cloud/src/functions/<组>/<fn>` → `npm run build:rw-cloud` → 按 §1.1 部署。回调类回滚期间未 ACK 的微信通知会重推，幂等设计不怕重。
- **静态托管**：构建目标 commit 的 admin/agent/site → §1.2 三步。
- **小程序**：微信后台「版本回退」回上一正式版。

可用的定位信息：回滚目标＝上一个 `deploy-*` tag（§1.1 部署账本；`node scripts/deploy-fns.mjs --dry-run` 对照当前产物）；`rewrite/cloud/dist/BUILD-INFO.json` 有 `sha`/`dirty`/`builtAt`，每函数 `package.json` 的 version 也是 `0.0.0-<sha>`。回滚只有单函数与小程序后台两条路，别假设一次成。

## 3. 凭证轮换

### 3.1 机制：`secureConfig` 集合「填即生效」
敏感凭证读取优先 `secureConfig/<docId>.<字段>`，为空才回退同名环境变量（`kit/secureConfig.ts` `ENV_FALLBACK`）。写入口唯一是 admin **`/config-checklist`** 页（`saveSecureConfig`/`savePayConfig`，零回显、仅超管、自动审计），填了下次冷启动即生效，不必重部署。

| docId | 字段 | env 兜底 |
|---|---|---|
| `wxkf` | corpId / secret / token / aesKey / agentId / miniappAppId / thumbMediaId | `WXKF_CORPID` / `WXKF_SECRET` / `WXKF_TOKEN` / `WXKF_AESKEY` / `WXKF_AGENTID` / `WXKF_MINIAPP_APPID` / `WXKF_THUMB_MEDIA_ID` |
| `wxpay` | mchSerial / mchPrivateKey | `WXPAY_MCH_SERIAL` / `WXPAY_MCH_PRIVATE_KEY` |
| `vod` | secretId / secretKey / playKey / procedure | — |

**⚠️ 不要用 `tcb fn detail` 查含密钥的函数**：它会明文打印环境变量。核对用长度或 hash，不打印值。

**环境变量里不留密钥**：`ADMIN_BOOTSTRAP_KEY` 首次登录建出超管后，必须立刻到云开发控制台从 `adminApi` 环境变量删除（它就是超管口令）。上表的凭证填进 `/config-checklist` 后，同名环境变量要从**每个**云函数上删掉：凡经 `kit/secureConfig.ts` 读凭证的函数，库里空着时回退的是它**自己**的环境变量，副本可能留在任何一个上面——商户私钥至少查 `adminApi`、`billReconcile`，`WXKF_SECRET`/`WXKF_TOKEN`/`WXKF_AESKEY` 至少查 `adminApi`、`kfCallback`、`kfHealthProbe`（完整名单以 `ENV_FALLBACK` 和 `getSecureConfig*` 的调用方为准）。先确认库里已有再删，库里空着就删会让对应功能拿不到凭证。`/config-checklist` 只看得到 `adminApi` 自己的环境变量（商户私钥、首登口令还在时标黄）；其余函数到控制台「函数配置 → 环境变量」逐个看有没有这个名字，不点开值。

## 4. 故障速查

统一起点：`tcb fn log <函数名> -e cloudbase-d4gcssqbv06865479 | grep '\[LD_ALERT\]'`（动作类失败都留结构化行）。异常还会进 `anomalies` 集合、按配置推企微群。

| 症状 | 方向 | 处置 |
|---|---|---|
| 付不了款 | 连接器/工作流失效、flowId 漂、notify_url 错 | 看 `app`（createOrder→callFlow）与 `payCallback` 日志 `[LD_ALERT]`；按 `console-assets/01` 核连接器凭证、主工作流已发布、flowId |
| 漏单（付了没进状态） | 回调未 ACK / 状态机卡 | `tcb fn log payCallback` 看是否收到回调；卡单由 inspect 逮；幂等，重推不重复 |
| 退款卡单 | `out_refund_no` 非法字符 / 工作流未结案 | `refundCallback` 日志找 `PARAM_ERROR ... out_refund_no`；单号须匹配 `^[0-9a-zA-Z_|*@-]{1,64}$` |
| 客服不回 | 验签/解密不过、token 失效、游标 stale | `kfCallback` 日志：`FORGED_CALLBACK`＝Token/AESKey 没对齐（§3.3）；`60020`＝可信 IP（§3.4）；`95012`＝用错 Secret（§3.2）；验签过但 `sync msgs:0`＝清 `kfState` 的 `cursor:<openKfId>`（别删 token/seen） |
| 坐席发送失败 `95018` | 该会话曾在企业微信原生接待台被接入（state 3） | 在接待台**结束该会话**即恢复；`send_msg` 只在 state=1 可发 |
| 卡单 / 死信（`PAID_BUT_OOS`） | 库存回补耗尽 / 关单退款异常 | inspect 的 `stuck-order` 逮进 `anomalies`；查 `[LD_ALERT]` + samples 单号，人工核对回补 |
| 超卖 | 并发扣减未守住 | 库存只由 `kit/inventory` CAS 读写；查 anomalies 的 oversold 类与 samples，核 `inventory` 与订单 |
| 后台登录被锁 | 认证频控触发 | 等锁定窗口过或核 `rateLimit` 集合该 key；看 `[LD_ALERT]` 有无爆破迹象 |
| 告警没收到 | webhook 未配/配错 | 日志和 `anomalies` 恒有；手机推送需 `adminConfig/settings.alertWebhook`（admin 设置页填） |
| 部署了不生效 | 云端 stale / 假部署 / 部署错对象 | 函数 `tcb fn list` 看修改时间、`tcb fn log` 看新代码特征（不用 `fn detail`）；托管核入口哈希（§1.2）；管理端只部署 `adminApi` |
| VOD 段播不了（url:null / 403） | playKey 未配 / Key 漂 / 域名或欠费 | `[LD_ALERT] fn=vod code=VOD_KEY_MISSING`＝填 playKey；403＝控制台 Key 与库内不一致（§3.7 顺序）；全黑＝查 VOD 余额与域名 CNAME |
| 转码卡在「转码中」 | 任务流没触发 / 转码失败 | admin 点「同步转码状态」；云点播控制台任务管理查该 FileId（仅存 72h）；procedure 名对照控制台；失败可控制台手动重发任务流 |
| admin 上传走了云存储而非 VOD | VOD 凭证未配全 | 预期行为：未配 VOD 自动回退云存储；要走 VOD 就把四项填全（负缓存 5 分钟） |
| 开发者工具白屏 / component not found / RPC 不回包 | 有状态共享实例被 build/自动化互踩 | 跑 build 前先停自动化；遇怪象先 `cli quit` + 重启再排查 |

## 5. 巡检与告警

**三头可观测**（一处失效另两头兜）：`[LD_ALERT]` 日志（`kit/observe.ts`）· `anomalies` 集合（admin `/anomalies` 页筛选、标记已处理）· 企微群机器人（`settings.alertWebhook` 配了才推，URL 是凭证不进日志）。

**云侧自动巡检**：
- `timers/inspect` 每 2 小时：基建存活 + 业务不变量（钱守恒、卡单/死信）→ 写 `inspectRuns`，红项进 `anomalies`，高危推告警；每日心跳报平安。手动触发：admin `/inspect` 页「立即巡检」或 `tcb fn invoke inspect`。
- `timers/kfHealthProbe` 每 30 分：探令牌/可信 IP 静默故障。`FORGED` 类测不了（需真消息），靠「动配置后必发测试消息」兜。
- `timers/billReconcile` 每日 11 点：拉前一日微信账单对账，差异进 `anomalies`。凭证走 `secureConfig/wxpay`；未配则每日静默 skipped，只在 `anomalies` 留 `BILL_RECON_NOT_CONFIGURED` 低级面包屑。

**每日巡逻**（纯本地、零写操作）：`npm run patrol`，Linux 工作机 systemd 每天 04:35 跑，日志 `/tmp/luckyducky-patrol.log`。六项：git 卫生（积压 >20 笔红）· 结构守卫快检 · SSL 剩余天数（≤30 天红）· 备份新鲜度（>26h 红）· Issues 数量 · npm audit 高危计数。

**端侧**：小程序后台「性能监控 / 实时日志 / 运维中心」三件套覆盖客户端崩溃与性能，发布后开启并绑定告警接收人（`docs/外部配置手册.md`）。

**日常看什么**：admin `/inspect` 红绿灯 + `/anomalies` 未处理数。

**触发器核验**（部署定时器后必做）：云开发控制台该函数的「触发器」页看仍挂、cron 对（不用 `tcb fn detail`：会打印环境变量）；到点后 `tcb fn log <定时器函数名>` 有新执行记录。现网期望值见 `console-assets/README.md`。

## 6. 备份与索引

- **自动备份**：Linux 工作机 systemd 每天 04:00 `npm run db:export`（`~/.config/systemd/user/luckyducky-db-export.{service,timer}`，linger 已开）→ `.db-backups.local/<时间戳>/`（`*.local` 不入库）。新鲜度由每日巡逻监督。备份与工作区同盘、单副本，可每周手动拷一份到移动盘。
- **手动导出**（只读：读集合→官方导出→下载本地）：
  ```bash
  npm run db:export                                  # 默认 P0 关键 10 集合
  npm run db:export -- --collections=orders,users     # 指定集合
  SECRETS_EXPORT_ALLOWED=1 npm run db:export -- --collections=secureConfig --include-secrets  # secureConfig 只落字段名、不落值
  ```
  `--include-secrets` 不带 `SECRETS_EXPORT_ALLOWED=1` 直接拒绝（退出码 1）。凭证不做备份：恢复时回各平台重新取。
  凭证优先 `TENCENTCLOUD_SECRETID`/`SECRETKEY`，否则走已登录的 `tcb secrets get --json`。恢复没有脚本：控制台「数据库→导入」或 manager-node `import()`，**导入前先核目标集合现状，防覆盖比备份新的数据**。
- **索引核对**（只读）：`npm run db:check-indexes`（全量对照 `console-assets/03-复合索引期望表.md`）/ `-- --priority=P0` / `-- --json`。退出码 0＝无 P0 缺失，1＝有缺失或读取失败，2＝拿不到凭证。

## 7. 出事与上线

**出事处置**：
1. 收到报警（企微群 / 平安报缺席 / 用户投诉）。
2. 定位：`gh issue list` + `/anomalies` + `tcb fn log`。
3. **止血先于修因**：单函数坏→§2 单点回滚；小程序坏→微信后台版本回退；托管坏→重发上一个哈希包；数据问题→先停相关写入再评估。
4. 修复走正常批次流程，不热改生产。
5. 记账：commit 信息 + Issue；新病根入 `docs/根因账本.md`。

**钱链/交易函数上生产后的冒烟**（部署成功、测试全绿都 ≠ 真能用）：
0. 先确认部署同步：`node scripts/deploy-fns.mjs --dry-run` 报 0 个待部署，或 `node scripts/preflight.mjs` 钱链漂移绿。
1. 只读先行：打开有真实数据的页，数字不崩不空不 NaN。
2. **正常路径不被误伤**：用真实在售商品走主流程，确认新校验没拦正常单（新拒绝逻辑最易误伤字段不规整的老数据）。
3. **真钱小额**：下单→付款→转已付→可退款，不用 mock。
4. 并发竞态真机复现不出，靠测试锁；真机只验正常路径。
任一步红 → 先停后续上线动作回查。

**对账差错**（后台「交易异常」`getTxAlerts` 亮起时；处置写 commit 或 Issue）：
1. **feeMismatch**（实付≠应付，发货被 `FEE_MISMATCH_HOLD` 挡）：商户后台核实收 vs 应付 → 真差额就补退 → 核实无误后 `clearFeeMismatch` 解除。**没核实前别清标发货。**
2. **refundMismatch**（退款回调单号/金额不符）：商户后台核真实状态与金额，人工核对售后单后记账。
3. **stuckRefunds**（approved 超 1h 无成功回调）：商户后台查退款状态，成功则等回调/人工核对，失败则重发退款工作流。
4. **refund_required**（已付但售罄，`PAID_BUT_OOS`）：商户后台凭 `transactionId` 手动全额退款后记账。

## 8. 意见反馈 → 工单

用户提交 → `feedback` 集合（只收集不处理）→ `feedbackNotify` 定时器推企微群 → 人工在云开发控制台 `feedback` 集合（按 createdAt 倒序）筛：广告/无意义忽略，真问题建 GitHub Issue。

- **反馈原文永不直接进模型上下文**：AI 只读人工提炼的工单（字段化、脱敏），链接/附件/可疑内容不复制进工单，反馈一律视为不可信数据（防提示注入与隐私风险）。
- 工单格式：标题一句话；来源写反馈文档 id（不复制原文）；类型 bug/建议/咨询；优先级（紧急线上 bug 直接标紧急）；脱敏描述；期望。
- `feedbackNotify` 部署后在控制台配定时触发（建议每日 09:00）；静音：`adminConfig/settings.alertEvents.NEW_FEEDBACK = false`。

## 10. 平台坑（本项目踩出、官方文档不写的）

**tcb CLI**（配置读项目根 `cloudbaserc.json`）
- `tcb fn invoke` 没有 openid 上下文：依赖用户态的 action 要从小程序端调（automator 在工具里 `evaluate` 调 `wx.cloud.callFunction`，样板 `scripts/mp-smoke.cjs`）。
- `--force` 更新不会在云端装依赖（只有新建才装）→ `cloudbaserc.json` 每个函数配了 `installDependency: true`；报 `Cannot find module 'wx-server-sdk'` 即此坑。
- `cloudbaserc.json` 缺 `memorySize` 会在下次应用配置时把现网内存打回默认；超时同理，改规格先改 `cloudbaserc.json`。
- `tcb login` 过期重登：浏览器授权页**选「微信公众号」扫码**（小程序管理员微信），不要用腾讯云账号密码。
- `tcb db nosql execute --command` 结构是 `[{"TableName":…,"CommandType":"QUERY|INSERT|UPDATE|DELETE|COMMAND","Command":"<字符串化的 Mongo 命令>"}]`，不是裸 Mongo 语句；直接写 live 库属敏感操作。
- tcb CLI 与 cloudbase-framework 等官方开源工具已归档停滞：升级前先验，别指望官方修坑；部署链坚持自研的 deploy-fns / guard-deploy，勿回退到官方 framework 一键部署。

**数据库**
- 只有小程序端 `add` 自动写 `_openid`；**云函数/控制台 `add` 不写**。云函数写的数据之后要按 `_openid` 查或鉴权，必须显式写入。

**平台限制**

| 限制 | 现象 | 解法 |
|---|---|---|
| HTTP 服务请求体约 100KB | 控制台传图失败 | 图片约 80KB 分片 |
| 大文件不走普通接口 | 视频传不动 | 浏览器直传云存储或 VOD |
| 看板单表一次统计 ≤1000 条 | 上万会少算 | 上量改预聚合 |
| 单文档 512KB | 课程/商品档案远未触及 | — |
| 冷启动 | 久未调用首响慢 1–2s | 体验毛刺非故障 |

**控制台**
- 工作流改完必须点「发布」，否则云函数调的仍是旧版。
- 证书序列号不能带空格（粘贴易混入，签名失败）。
- paynotify 有两条同码转发节点互为保险，删任一条前确认另一条在跑。
- 平台规则会单方面变（云调用支付曾被整条封死改走工作流），接缝都收在 kit 单点，变了改动面最小。
