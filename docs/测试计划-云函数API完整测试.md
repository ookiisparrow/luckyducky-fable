## 三、功能测试（上午 2h）

### 3.1 测试方式
- 用 node-sdk `callFunction` 直调云函数（模拟小程序调用，无需 HTTP 端点）——已具备密钥
- adminApi 另走 HTTP 端点验证鉴权链（若端点就绪）

### 3.2 用例设计（正常/边界/异常三维）
选取核心 action 覆盖，约 30~40 条用例：

| 分类 | 场景 | 示例 action | 验证点 |
|---|---|---|---|
| 正常 | 读列表/详情 | listProducts / getProductDetail / listOrders | 返回结构、分页、状态过滤正确 |
| 正常 | 写操作 | saveDraft / shipOrder / approveRefund | 落库正确、返回 ID/状态 |
| 边界 | 空参数/缺参 | 各 action 缺必填字段 | 返回明确错误码，不崩 |
| 边界 | 非法 ID/越界分页 | getOrderDetail?id=不存在的 | 404/空结果，不异常 |
| 边界 | 超长输入/特殊字符 | saveDraft 名称超长/含 emoji | 截断或报错，不注入 |
| 异常 | 未认证 | 无 key / 错 key | 401 BAD_KEY |
| 异常 | 越权 | 低权限账号调 admin:write action | 403 拒绝 |
| 异常 | 频控 | 连续快速调用 | 429 限频生效 |

### 3.3 通过标准
用例通过率 100%；失败用例必须区分「产品缺陷」与「环境问题」。

## 四、性能测试（高并发 2h + 恒测 2h）

### 4.1 高并发（k6 或 wrk）

**测试对象**：adminApi 读型接口（listOrders/listProducts）+ app 用户端首页接口
**并发梯度**：10 / 50 / 100 / 200，每档持续 5 分钟
**指标**：

| 指标 | 目标（建议） |
|---|---|
| TPS（吞吐） | 记录各并发档实测值 |
| 延迟 P50 / P95 / P99 | P95 < 500ms（可协商） |
| 错误率 | < 1% |
| 限流行为 | 超限时优雅 429，不雪崩 |

**注意事项**：
- 测试用隔离数据/只读接口为主，避免污染业务数据
- 200 并发档若触发环境限流（EXCEED_RATELIMIT），记录实际上限并降档
- 冷启动毛刺（首次调用 1-2s）不计入 P95 统计（预热后计）

### 4.2 恒测（稳定性/soak test）

**方式**：10 并发持续 **2 小时**，每分钟记录一次：
- 响应时间（P50/P95 曲线）
- 错误率曲线
- 云函数内存（通过 tcb 控制台/API 采样）

**通过标准**：
- 内存增长率 < 5%（无泄漏）
- P95 波动 < 20%（不随时间恶化）
- 全程无持续性错误

**说明**：小程序云函数是无状态的（Serverless 按调用计费），内存泄漏主要看云函数实例的持续响应退化——用响应时间曲线间接监控。

## 五、安全测试（下午 1~2h，仅非破坏性）

| 项 | 方式 | 范围 |
|---|---|---|
| 认证绕过 | 无 key/错 key/伪造 token 调受保护 action | 验证 401/403 生效 |
| 越权测试 | 低权限账号访问高权限 action | RBAC 能力位校验 |
| SQL 注入 | action 参数注入 `' OR 1=1` 等（云数据库查询） | 参数化查询验证，非破坏性 |
| XSS | 名称/内容字段注入 `<script>` 后读出 | 验证转义（云开发后端非渲染端，风险低） |
| 敏感信息 | 错误返回是否泄露堆栈/密钥 | 响应体检查 |
| 限频绕过 | 频控机制是否可被并发绕过 | 观察 429 是否稳定 |
| 漏洞扫描 | Nuclei 扫 HTTP 端点（若端点就绪） | 仅轻量模板，无破坏性 payload |

**安全红线**：不做 DoS、不删数据、不碰生产环境。

## 八、风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| HTTP 端点未绑定 | 高并发只能打 node-sdk 直调（非标准 HTTP） | 提前确认/绑定端点；不行则用直调方案 |
| 代理/网络不稳定 | 压测中断 | 压测关代理直连；失败重试 |
| 环境限流（EXCEED_RATELIMIT） | 高并发档位上不去 | 记录上限，降档测试 |
| 测试数据污染 | 影响业务判断 | 只读接口为主 + 测试数据带标记 + 跑后清理 |
