# luckyducky-fable 一键真机调试

把 `rewrite/mp` 小程序自动推送到真机运行，一条命令搞定，无需手动点击开发者工具界面。

## 快速上手

```bash
# 检查微信开发者工具连接状态
npm run device:status

# 一键推送到真机（推荐）：编译后直接推送到开发者微信，微信点开预览卡片即真机运行
npm run device:preview

# 真机调试（带调试器）：触发工具的真机调试流程，手机端需扫码/确认
npm run device:debug

# 打开项目窗口
npm run device:open
```

也可以指定页面：

```bash
npm run device:preview pages/detail/detail
```

## 技术方案

**核心原理：微信开发者工具内置 HTTP MCP 服务，用普通 HTTP 请求直接调用其 MCP 工具，无需任何 MCP 客户端。**

- 微信开发者工具（≥ 1.06.241112）在运行时会开启一个本地 HTTP 服务端口（本例为 `57454`，每次启动可能变化），该端口提供 `POST /mcp` 的 MCP over HTTP 端点。
- 脚本自动探测端口（依次尝试 9420/9421/9422，再扫描工具进程监听的端口），无需手写端口。
- 关键 MCP 工具：
  - `auto_preview`：把预览**直接推送到开发者微信**（无需二维码），微信端点开即真机运行 —— **本方案的主路径**
  - `automation_viewport_action`（action=`remote` + auto=true）：触发真机调试
  - `open_project_window`：打开项目窗口
  - `check_wechatide_status`：查询登录态

> 为什么不用 CLI 的 `preview` 命令？实测 CLI 版 `preview` 在当前版本存在"二维码输出路径无效"的 bug；且 CLI 需要 `--port` 手动指定。MCP 方式更稳定、能力更全。

## 前置条件

1. macOS 已安装微信开发者工具（本机版本 36.6.0，路径 `/Applications/wechatwebdevtools.app`）。
2. 微信开发者工具已启动并登录（登录账号需为小程序 `wxcbd2fb68b81bcfb1` 的项目成员）。
3. 手机与电脑处于同一网络（WiFi 即可；微信预览走微信通道，不要求 adb/数据线）。

## 工作原理（说人话版）

- `device:preview`：脚本 → 找到工具的 MCP 端口 → 调 `auto_preview` → 工具编译代码包（~1MB）→ 推送到开发者微信 → **微信里出现预览卡片，点开即真机运行**。全程只有"点开卡片"这一个动作。
- `device:debug`：脚本 → 打开项目窗口 → 触发真机调试 → 工具弹出真机调试二维码 → **手机微信扫码 + 确认** → 真机连接调试器（可看 console、网络、元素）。

## 常见问题

| 现象 | 原因与解决 |
|---|---|
| `未找到微信开发者工具的 MCP 服务` | 工具未启动或未登录。先手动打开微信开发者工具并登录，再重试。若仍失败：设置 → 安全设置 → 开启「服务端口」。 |
| 真机调试一直等待 | 微信安全机制要求手机端扫码/确认，属正常现象。请在工具窗口扫码、手机端点允许。 |
| 预览卡片在微信里没看到 | 预览推送到的是**开发者本人的微信**（即工具登录账号对应的微信），确认是同一个微信。 |
| 端口每次变化 | 正常。脚本会自动探测；也可在工具设置里固定服务端口后用环境变量 `WX_DEVTOOLS_PORT=9420` 指定。 |

## 脚本入口

- `scripts/real-device.mjs` —— 主脚本（Node ≥ 20，无需额外依赖）
- 环境变量 `WX_DEVTOOLS_PORT` 可手动指定端口

## 已知限制

1. **微信扫码确认不可绕过**：微信安全机制要求真机运行/调试必须经过微信端确认，这是平台底线，无法全自动跳过。
2. **真机调试（debug）需要人配合扫码**：`auto_preview` 是唯一接近"零操作"的真机运行方式。
3. 需求原案中的"安卓原生应用真机调试"因项目不存在安卓工程、环境未装（JDK/Gradle/SDK/adb）且无真机，经确认已从本次范围中移除。
