# 工作流（版本 1.0 · 2026-08-22 立）

> 上线前立的完整工作流正册：写码→验证→发布→巡检→回滚 全链路，机器闸在必要环节审核。
> 设计原则：**高频判断轻的事给机器（查/报/拦），低频不可逆的事留给人（改生产/发版），但人按按钮之后的过程全部机器化。**
> 本文件只写「现在真实存在的机制」；没建的写进 §5 路线图，不冒充已有。

## §0 一张图

```
写代码 ──→ 三道闸(check) ──→ 推 main ──┬─→ 【云函数】发测试环境 yaliceshi 冒烟 → 授权发生产(DEPLOY_ALLOWED)
                                      ├─→ 【小程序】真机预览 → 体验版 → 提审 → 正式版（微信后台·人工）
                                      └─→ 【admin/site】构建 → 发托管 → 哈希核对
每天 04:35 巡逻(npm run patrol) ──→ 全绿=平安报 / 有红=Issue+处理指引
出事 ──→ 定位(Issue/巡检/anomalies) ──→ 单点回滚或热修 ──→ 复盘记账(commit+Issue)
```

## §1 各环境单源

云门牌真值＝`scripts/lib/env.mjs`（`ENV_CATALOG`）。查当前解析：`npm run env:resolve`（不连云、不要密钥）。

| 选择子 | 用途 | 可否写入 | git |
|---|---|---|---|
| `stub` | 内存桩·单测/断言 | 否 | — |
| `test` | 测试云（压测/测部署/test-api） | 是（须 `--target test`） | `test` |
| `prod-readonly` | 生产只读（巡检/断言） | 否 | `main` |

生产写入只走 `deploy-fns` + `DEPLOY_ALLOWED`，本目录不开放「prod-write」。小程序 AppID 与库备份见下：

| 面 | 用途 | 状态 |
|---|---|---|
| 小程序 `wxcbd2fb68b81bcfb1` | devtools→真机预览→体验版→提审→正式版 | 待上传 |
| 数据库 | 生产共用一套集合；测试云可做恢复演练靶场 | 备份链 ⚠️ 见 §3 |

怎么选：

```bash
npm run env:resolve -- --target stub
npm run env:resolve -- --target test
npm run env:resolve -- --target prod-readonly
node scripts/loadtest.mjs --target test --mode cas
node scripts/deploy-test.mjs --target test
```

## §2 机器闸清单（谁拦谁）

| 闸 | 拦什么 | 开锁方式 |
|---|---|---|
| 提交闸（pre-commit） | check 不过的提交 | 无（--no-verify 不建议） |
| 红区闸（pre-commit 内） | 钱链路径提交 | `MONEYCHAIN_ALLOWED=1`（老板授权） |
| 部署闸（guard-deploy） | 云函数/托管的部署命令 | `DEPLOY_ALLOWED=1`（老板授权） |
| MCP 写工具 deny | AI 直调云端生产写工具 | 不可解锁（白名单 fail-closed） |
| 守卫正册（117 条 check:structure） | 结构/契约/计数漂移 | 改代码到绿，不绕闸 |

## §3 每日巡逻（已建成·真实跑通）

- **命令**：`npm run patrol`（纯机器层·零写操作·爆炸范围=0）
- **六项检查**：① git 卫生（积压>20 笔红）② 结构守卫快检 ③ SSL 证书倒计时（≤30 天红）④ 备份新鲜度（>26h 红）⑤ Issues 数量 ⑥ audit 高危计数
- **排程**：Linux 工作机 systemd 每天 04:35 跑 `npm run patrol`（与 §3.5 备份同机；原 Mac launchd 已退役）。日志落 `/tmp/luckyducky-patrol.log`。
- **AI 判断层**（可选升级）：Paseo schedule 定时唤起代理读巡逻输出做归因开 Issue——daemon 启动后加（`paseo daemon start`）。当前纯机器版已够用。
- **2026-08-22 首跑战果**：抓到备份断流 13 天、q.luckyducky.cn 证书域名不匹配（HTTPS 实际是坏的）、www/kf 证书剩 24 天。

## §4 出事处置路径（上线后照此走，不手忙脚乱）

1. **收到报警**（企微群推送 / 平安报缺席 / 用户投诉）
2. **定位**：`gh issue list` + anomalies 账本（admin 后台 Audit 页）+ `tcb fn 日志`
3. **止血优先于修因**：
   - 单函数坏 → 按 `docs/运维手册.md` §2 单点回滚（分钟级）
   - 小程序坏 → 微信后台「版本回退」一键回上一正式版
   - 托管前端坏 → 重发上一个哈希包
   - 数据问题 → 先停止相关写入动作，再评估（有备份可恢复）
4. **修复**：按正常批次流程改（守卫全绿才提交），不热改生产
5. **复盘记账**：commit 信息 + Issue 关闭 + 若新病根入 `docs/根因账本.md`

## §3.5 数据库备份（唯一链路·最简路径）

- **链路**：定时任务每天 04:00 `npm run db:export` 直连云导出 → `.db-backups.local/<时间戳>/`。单机单命令，无跨机依赖。
- **执行机**（2026-08-23 迁机更新）：Linux 工作机，`~/.config/systemd/user/luckyducky-db-export.{service,timer}`（linger 已开）。原 Mac launchd 方案随旧机退役。
- **新鲜度监督**：巡逻④（04:35）查备份年龄 >26h 即红——断链机器自动喊人。
- ⚠️ 单机单副本风险：备份与工作区同盘。后续可加「每周手动拷一份到移动盘/网盘」，暂不建自动链路（保持最简）。
- （旧跨机备份链已于 2026-08-22 废弃，经过与根因见 git 历史。）
