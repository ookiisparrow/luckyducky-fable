## 12. 激活码不绑订单（备货封码）+ 退货验收扫码兜底

决策（2026-06-10）：唯一激活码按「一款产品的配套课程」批量生成、打印，**备货阶段**封入该产品每个包装并封装——码只属于（courseId, batchId），**不与订单/订单条目绑定**（取消原「发货时绑订单条目」环节）。条目级退货权的执行改为两层：① `confirmEnter` 时**启发式自动失效**（确认者本人订单中含该课程对应商品的可退条目，取最早一条 `refundable=false`）；② **强制兜底 = 退货验收扫码**（退货须寄回完整包装，验收扫包装内码：已激活 → 该件拒退；未激活 → 正常退）。

原因：

- 用户明确的备货流程：码在备货时封入包装——发货拣货时拿到的是已封装的盒子，无从知道盒内是哪个码，「发货绑定」物理上不成立；内外双码方案被否（多一份物料 + 多一个发货扫码动作）。
- 验收扫码让退货权的最终裁决回到**物理凭证**：码随包装走，谁退货谁交回码。不依赖订单绑定，自购 / 送礼一致有效（收礼人激活 → 买家手里没有完整包装可退；买家退未拆封件 → 码未激活，正常退）。

代价（与对策）：

- `refundable` 自动失效只在自购场景命中（启发式），送礼场景订单条目标记不更新 → 该字段降为**展示性标记**，App 内提示用，裁决以验收扫码为准。
- 退货权执行依赖运营纪律：**退货必须要求寄回完整包装 + 验收必扫码**，需写进退货政策与验收 SOP；客服需理解「标记」与「裁决」双轨。
- 启发式匹配在「同用户多笔同商品订单」时取最早可退条目，可能与用户心理预期的那一单不一致 → 展示层面说明即可，不影响裁决。

## 13. 二维码类型：普通链接二维码（一码一地址）

决策（2026-06-11，用户拍板）：印刷物料走**普通链接二维码**——每个激活码对应一个网址（`https://<域名>/q/<激活码>`），网址清单交印刷厂，「一个地址印一个码」。不用小程序码（`wxacode.getUnlimited` + scene）。

原因：
- **印刷流程最简**：交付物是一列文本网址，印刷厂自己出码图，我们不逐码调接口生成图片。
- **码本身可读**：网址尾段就是激活码，客服和退货验收肉眼可查。
- **不占小程序码接口**；URL Link 已不支持永久有效，印刷物料要活数年，直接出局。
- 微信外扫码落到该网址，可放「请在微信中打开」引导页。

代价：依赖 ICP 备案域名 + 小程序后台「扫普通链接二维码」规则；**规则配好、真机扫码通过前不许批量印刷**。

## 14. 视频上传控制台：自建网页编排页

决策（2026-06-11）：课程视频上传与编排做**自建网页控制台**（课程→章节→课时→小段三层编排、拖拽排序、原地改名、分段上传、**草稿与发布分离**：`coursesDraft` 编辑、发布时覆盖 `courses`）。

原因：三层嵌套结构 CMS 表单做不了；电脑端传大视频远比手机顺手；草稿/发布分离让编辑过程不影响线上学员。视频存储最初用云存储，后由 §31 升级为腾讯云点播 VOD。

## 15. 控制台主轴 = 商品上新流水线（商品建档进自建控制台）

决策（2026-06-11，用户明确逻辑层级）：管理控制台以**商品**为主轴组织：创建商品 → 上传产品图片 → 填写 SKU → 上传编排配套教学视频 → 设计二维码卡片（可自定义尺寸）→ 批量生成二维码地址，**打包下载 SVG 设计图 + 地址清单**交印刷厂。

原因（收益）：

- 与真实业务动线一致：上新就是「一款商品走完六步」，比按工具分模块（课程/卡片各一摊）更不容易漏步骤。
- 商品图片在控制台上传后直接喂小程序商品页——真实素材替换灰占位有了正式入口。
- SVG 矢量交付印刷厂，配合「一地址一码」的既定工作方式（§13），印刷链路全自动化。

代价（与对策）：

- 商品建档、图片、SKU 的写路径全部收口到自建控制台的云函数。

## 16. 管理台形态升级：一比一所见即所得橱窗

决策（2026-06-11，用户提出）：小程序信息（排序、上下架、文案等「长什么样」的内容）的管理形态定为**一比一所见即所得**——控制台内嵌手机框预览（iPhone 17 比例，用户指定），与小程序同一份云端数据渲染，在画面上直接拖动/编辑，与右侧面板双向联动。

原因（收益）：非技术运营者零学习成本（看到的就是用户看到的）；数据本就同一份、设计 token 共用，等价渲染成本低；为「小程序信息全面可管理」铺路。

代价（与对策）：等价组件需随小程序 UI 改版同步维护 → 只复刻「可管理区块」关键视觉。

影响：products 的 featured 语义 = 首页橱窗位。

## 17. 代码按技术分层组织（package-by-layer），不按业务链重组

决策（2026-06-11，用户提出并拍板）：代码保持**按技术分层**组织，**不**改成按业务链分文件夹（package-by-feature）。每条业务链的整体视图由 `docs/业务逻辑架构.md` 提供——逻辑上集合、物理上分布。

原因：
- **硬约束**：① 每个云函数是独立部署单元，其「云端那一半」无法并入某条链的功能文件夹；② admin/agent 是独立构建部署的工程；③ 共享代码跨多条链复用，按功能切会被迫复制（破坏单一来源）或进 `shared/`（又散回去）。
- **软代价**：按功能重组要改全部 import 路径，回归风险高，不为整洁动工作代码。

影响：新增功能按各包的技术分层放置（小程序 `pages → lib → api`，云端按域进 `rewrite/cloud/src/functions/<域>/`），页内自用代码就近放页面目录；**业务链或状态机变化时，先改 `docs/业务逻辑架构.md` 再动代码**。

## 19. 客服 = 微信客服官方组件（R18）

决策（2026-06-30 定稿）：
- **渠道**：独立**微信客服**（经同主体企业微信自建应用托管），小程序各入口统一走 `utils/customerService.ts` 的 `wx.openCustomerServiceChat`；不用功能简陋的 `open-type=contact`。
- **定位**：多触点接住 + 统一 360 + 按意图分流——订单/售后走微信客服（bot + 360 自动答）；钩织学习求助引导加企微做私域（入口话术用功能性描述，避开诱导红线）。
- **360 坐席台自建**：现有集合已覆盖 360 数据源大半，自建最省、最灵活、数据自主。不买付费客服 SaaS（5 个坐席以上再议），不上有赞/微盟中台（锁数据）。外包坐席用自建工作台、不进企微；内部企微侧栏按需再做。
- **身份桥**（external_userid → openid，经 unionid 反查）是 360 的命门。
- **微信小店只做分发渠道**：「材料包 + 激活码 + 课程」捆绑且激活链绑 openid，装不进小店；小店只宜引流款。
- **AI 选腾讯混元，时机押后**：咨询量起来、关键词兜不住再上。

## 20. 物流方案（R17 + 发货合规）

决策（2026-06-15，用户拍板，先调研微信官方规范再定）：物流分**两件不同的事**，分别定。

**① 发货信息管理（强制合规·非选做）**：凡微信支付卖实物的小程序，支付后须向微信上传发货信息（`upload_shipping_info`，用小程序自己的 AppSecret，**与快递公司 API 无关**），否则订单资金冻结、无法结算。已接进发货链：admin 发货时经 `kit/shipping.ts` 自动上传，失败只告警、不回滚发货（业务逻辑架构链 5）。

**② 物流轨迹展示（R17）**：决策＝上 **快递100「快递跟踪」免费小程序插件**。理由：直连快递公司 API 难（要签约/资质），但聚合服务商（快递100/快递鸟）已对接 1000+ 快递，只给「公司+单号」即返回轨迹、**小店不用碰快递公司**；快递100 插件对第三方小程序免费、模板化几小时接入、小程序内直接看轨迹不跳出。**风险**：快递100 服务市场已下架，复制兜底常驻。

**③ 运单下单（物流助手·电子面单）跳过**：适合发货量大要批量打面单的店；卖家现手动用顺丰寄，初期不碰。

## 22. 故意不抽象：投机泛化默认拒绝（YAGNI / Rule of Three）

决策（2026-06-25，用户拍板）：**默认拒绝投机抽象**——内联具体优先；新增接口/层/泛型/配置项须有当下真实需求，理由是「万一以后/方便将来」就删；相似两段先问「本质相同还是碰巧像」，宁可先重复，第三次再抽。`CLAUDE.md`「防过度工程」是写码时的尺，本条答为什么。

为什么：守卫体系整套在防「做得不够」，自带反向风险——守卫越堆、抽象越厚。过度工程＝替用户没给的数字（规模/寿命/用途）瞎猜天花板；错误抽象比重复更贵。

边界：**未来式 ≠ 投机式**。遇到「以后/预留/将来」先三分流：① 能追到需求清单、决策或用户明确意图＝保留；② 只有泛泛未来收益＝删或延后；③ 来源不明＝先问。这是判断题，靠人不配守卫（硬上守卫本身就是过度工程）。

判例：商品不引 xCounts（草稿量小，前端计数即诚实）；客服域不立状态机空册（§21）；不装 CMS（§11）。

**架构底线（2026-07-04，读《架构整洁之道》后定）**：采纳五条——依赖方向单向无环（印证 §17）；业务规则可脱离环境测试（内存桩）；平台接缝依赖反转、单点收口（这是留云开发又保留迁移自由度的技术根据，§23-4）；框架不绑架架构；测试是一等公民。拒绝三条——四层同心圆 + Repository/DTO 全套样板（云函数天然就是用例单元）；给每个集合建 Repository 的全面数据库抽象（迁移自由度靠 kit 接缝就够）；「微信可抽象」幻觉（openid、支付回调、扫码激活是业务土壤，不是可替换的外层细节）。

## 23. fable 重写定标：整体重写 · 按端选栈 · web 内容站（2026-07-03）

决策（2026-07-03，用户三轮对齐逐项拍板；依据 = Phase A 六维深度理解调研）：

1. **定性 = 重写，非重构**：深度理解业务需求与根本目标后整体重写，可摆脱所有非根本目标的枷锁。现系统定性为「前端 demo 派生→全局重构」的产物，受限于当时技术认知与上一代 AI 模型能力。
2. **承重柱维持 A（电商+锁课）**：计数陪伴（god-view 提议的 B 方向）继续留探索区，重写**不**为其做投机预留（守 §22 YAGNI）；内容模型沿用课程结构。
3. **微信端栈 = 原生 TypeScript + glass-easel，默认 WebView、关键页按页开 Skyline**——**推翻早期选 uni-app 的核心前提**（多端发布已不成立；DCloud 无 Skyline 适配）。Skyline 生态组件库不适配、PC 端自动降级，所以按页混用灰度，押注可一行配置撤回。**早期「暂不用 TS」口径同时废止**（cloud 已全量 TS，新系统全栈 TS）。
4. **后端留微信云开发，云函数全部重写**：最大锁定面 = 微信支付连接器（凭证在控制台正册资产），留平台则支付资产/数据/域名原地、切换风险最小；kit 接缝收口保留将来迁自建的自由度（openid 绑 AppID 不绑后端）。数据零迁移：集合复用 + 确定性 `_id` 双向兼容。
5. **web 端 = Astro SSG 教程内容站 + 官网（案二）**：**改写 T1 分发范围**——小程序对站外一切搜索/AI 引擎不可见，客群主阵地小红书禁爬非 AI 语料源，web 内容站是自控 GEO 语料源（公众号版喂元宝、web 版喂 DeepSeek/Kimi/百度）；**成交全留小程序**（H5 商城国内证据最弱，不做）。T1 代码不变量（交易只连云）不松。
6. **后台 admin + agent 一并重写，栈保留 Vue3+Vite**（现栈健康非病根，重写代码与信息架构）。
7. **旧铁律「永不重生成真机验过的运行时/UI」退役**：用户拍板 **UI 也可重设计**（可借 Skyline 转场/手势升级视觉交互），验收基准随新设计重建——工期与重新真机验收的代价已明示接受。

## 26. 退款规则：客户端一行一售后（刻意）+ 客服端管理员越规退款（净新增·超旧线 parity）（2026-07-05）

决策（2026-07-05，深审揪出「退款被拒后同行永久锁死」后用户拍板）：

- **客户端「一行一售后」定为刻意**：`applyRefund` 每行只能申请一次退款，被拒后同行永久锁死（确定性 `_id=orderId__lineId` + 跨全状态重复检查）＝有意设计，复议走客服端。不改客户端。（2026-09-29 补：老板点选加「顾客撤回申请中的售后」——顾客自己撤回的（withdrawn）不算占行，可重新申请；被拒仍永久锁死不变。）
- **客服端管理员越规退款＝新增能力**：管理员凭「退货管理」权限（新 cap `refund:manage`·超管 `'*'` 天然含）可**越过资格规则**（一行一售后锁/拒后锁死/已进课不可退）主动发起退款。落 `overrideRefund` action（`rewrite/cloud/.../adminApi/actions/refunds.ts`）。
- **钱守恒红线保留**：越规越的是「能不能退」，不越「退多少」——退款额仍 ≤ 该行实付分摊 − 全单已退（`refundShareFen` 单源公式封顶，退超实付被 `NOTHING_LEFT` 挡）。退超实付不是退货规则、是资损洞，绝不越。
- **留口**：若将来要「善意补偿超分摊额」＝另立补偿 action（越钱守恒需专门决策），非本动作。

## 30. tab 页误触退出提醒：用 `page-container`，`enableAlertBeforeUnload` 判废

决策（2026-07-14，查官方文档、社区真机报告并对抗验证后定论；此前翻过三次）：
- **只有一条路**：tab 栈底页（返回＝退出小程序）的误触提醒只能用隐形 `<page-container>` 做「再按一次退出」，且只可靠覆盖安卓返回键。

## 33. 治理原则：减法、四步流水线、文档只留规矩

**减法原则**（2026-07-23，用户拍板）：每个存在物（文档/守卫/脚本/依赖/接口/skill）必须答得出「谁在消费我」——只有历史价值不算（git 已存），答不出即退役。防漂移靠**零副本**：客观事实只留代码单源 + 指路。涉生产代码的减法只提案、由老板定。删减必须配「抢救复核」（专门找消费者救活它）——首轮 28 个候选救回 14 个，不复核就会误杀。

- 守卫只留钱/权限/状态/部署、编译器替身、手抄副本同步三类（准入表在 `.claude/skills/refactor-batch/SKILL.md`「守卫准入」），120 条砍到 72 条；skill 11 个并成 6 个；`CLAUDE.md` 不手抄守卫名、代码注释引用它不带章节号。

**红区提交闸合一**（2026-09-25）：原钱链闸（pre-commit·`MONEYCHAIN_ALLOWED`·21 路径）与红区复核闸（commit-msg·`[red-review: 复核人]`·钩子里另写死 13 个文件）有 8 个文件重叠，`modules.json` 的 tier 又是第三份红区定义且没有代码读它。合成一份名单 `scripts/lib/red-paths.mjs`（两份取并集，再补上从没被任何闸管过的关单/对账定时任务与云端入口/后台认证 5 个文件）+ 一个口令 `RED_ALLOWED`（须人手动敲，AI 自设会被权限拦）；删 commit-msg 钩子与 tier 字段。提交信息标签 AI 自己就能写、拦不住什么，谁复核过由「人合并 PR」体现。名单读不到时按红区拦下（fail-closed）。

**文档只留规矩**（2026-09-25）：每份文档要答得出「为什么单独存在」；能从代码、git 或另一份文档得到的不另立。状态与待办只放 GitHub Issues，过程史只放 git。docs/ 收成六份：需求清单（做什么）、业务逻辑架构（怎么跑）、关键决策记录（为什么）、根因账本（病根字典）、运维手册、外部配置手册。skill、执行者错题本、控制台正册同理。引用用章节名不用章节号。

**不绑定特定代理**（2026-08-02）：护城河是守卫、测试、文档与 `npm run check`，不依赖某个 AI 代理；skills、hooks 是可再生层。`AGENTS.md` 只指向 `CLAUDE.md`。第三方工具接 Anthropic 订阅 OAuth 属条款灰色地带，不拿来跑生产。

## 34. 小程序品牌字体：圆体只留给界面文案，正文和用户内容走黑体

决策（2026-09-28，老板拍板，随 v5「字重」设计稿）：文源圆体只用在按钮、标题、界面固定文案；正文长段、说明文字、13px 及以下的辅助小字（按键除外）和用户自己填的内容（昵称、收件人、地址、评价、输入框）一律用黑体（`.t-sys`）。取代旧口径「整页正文也用圆体」。
- **为什么**：设计稿就是这么分的；圆体要远程下载子集，字越多越重。用户内容什么字都可能出现，要显示完整只能囤 GB2312 一级 2870 字（每字重约 790KB）。改成黑体后字体子集只收真用圆体显示的字；设计稿的细体（300）只用在小字上，小字也走黑体后圆体只出 500/700/900 三档。全套下载从约 2.4MB 降到 0.5MB 以内（以构建输出为准）。
- **挑字口径**（单源 `scripts/lib/brand-font-charset.mjs`）：不收 `.t-sys`/`.mono` 子树、输入框、系统弹窗/提示的参数、云端报错文案；代码里 20 个汉字以上的字面量当正文不收（页面上必须挂 `.t-sys`）。
- **代价**：昵称/收件人/评价人名字与设计稿不同（稿里是圆体）；按键上的小字（「编辑」「换」、标签键等）从稿里的细体改成 500。后台新上架的商品名不在 seed 里会逐字掉成黑体，上新后要重建字体并部署托管 `/fonts/`。

## 40. 受托客服数据共享「登录即默认开启、可随时撤回」（2026-09-30，老板）

与 §36「按委托处理走」同向的过渡做法（律师确认前）：委托处理本不需要单独同意，这里再给用户一个撤回的选择。
- 默认开启只在「已同意协议」的登录里写（登录接口带 agreed：登录半屏刚勾协议传 true；「我」页/编辑资料/授权页按本机是否已同意协议传），**未勾协议的静默识别永不写**；只给从没自己选过的用户写（`csDataShare.via='login'`），主动撤回/开启过的一律不覆盖；删资料被重置的（at===deletedAt）重新登录按新用户处理。
- 登录半屏协议勾选下方告知「登录即默认开启受托客服数据共享，可随时撤回」；隐私政策第三条、授权页第二段改写（老板定稿）。
- 授权页只放一颗浅色键：**服务端确认已撤回**才给「重新开启」，其余（已开启/未知/拉取失败）一律「撤回授权」——本机提示可能过时，保证任何时候都撤得回。
- 注意：若律师认定需第 23 条「单独同意」，登录默认同意属捆绑、不成立，届时回到显式同意；若确认委托处理，按 #420 可进一步移除同意闸。
