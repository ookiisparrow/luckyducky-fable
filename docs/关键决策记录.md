## 11. 不装云开发 CMS，控制台全部自建

决策（2026-06-10）：控制台全部自建（§14–§16），云开发 CMS 不装。将来出现「批量人工修数据」这类 CMS 独有的高频需求再装（数据始终在自己的集合里，进退成本都低）。

## 12. 激活码不绑订单（备货封码）+ 退货验收扫码兜底

决策（2026-06-10）：唯一激活码按「一款产品的配套课程」批量生成、打印，**备货阶段**封入该产品每个包装并封装——码只属于（courseId, batchId），**不与订单/订单条目绑定**（取消原「发货时绑订单条目」环节）。条目级退货权的执行改为两层：① `confirmEnter` 时**启发式自动失效**（确认者本人订单中含该课程对应商品的可退条目，取最早一条 `refundable=false`）；② **强制兜底 = 退货验收扫码**（退货须寄回完整包装，验收扫包装内码：已激活 → 该件拒退；未激活 → 正常退）。

原因：

- 用户明确的备货流程：码在备货时封入包装——发货拣货时拿到的是已封装的盒子，无从知道盒内是哪个码，「发货绑定」物理上不成立；内外双码方案被否（多一份物料 + 多一个发货扫码动作）。
- 验收扫码让退货权的最终裁决回到**物理凭证**：码随包装走，谁退货谁交回码。不依赖订单绑定，自购 / 送礼一致有效（收礼人激活 → 买家手里没有完整包装可退；买家退未拆封件 → 码未激活，正常退）。

代价（与对策）：

- `refundable` 自动失效只在自购场景命中（启发式），送礼场景订单条目标记不更新 → 该字段降为**展示性标记**，App 内提示用，裁决以验收扫码为准。
- 退货权执行依赖运营纪律：**退货必须要求寄回完整包装 + 验收必扫码**，需写进退货政策与验收 SOP；客服需理解「标记」与「裁决」双轨。
- 启发式匹配在「同用户多笔同商品订单」时取最早可退条目，可能与用户心理预期的那一单不一致 → 展示层面说明即可，不影响裁决。

## 13. 二维码类型：普通链接二维码（一码一地址）

决策（2026-06-11，用户拍板）：印刷物料走**普通链接二维码**——每个激活码对应一个网址（形如 `https://<域名>/q/<激活码>`），把网址清单交给印刷厂，「一个地址印刷一个二维码」。放弃原推荐的小程序码（`wxacode.getUnlimited` + scene）。

原因（收益）：

- **印刷流程最简**：交付物是一列文本网址，印刷厂自己生成二维码图样，我们不用逐码调接口生成图片文件再交付。
- **码本身可读**：网址尾段就是激活码，客服 / 退货验收人员肉眼可读、可手工查询，不依赖扫码设备。
- **不占小程序码接口**：无生成量与频率的接口依赖；URL Link 方案则因微信已不支持永久有效链接，印刷物料（要活数年）直接出局。
- **域名落地页有余地**：微信外扫码会落到该网址，可放一页「请在微信中打开」引导（静态托管即可）。

代价（与对策 / 依赖）：

- **依赖一个 ICP 备案域名**：微信「扫普通链接二维码打开小程序」要求域名已备案 + 在小程序后台配规则（前缀绑定 welcome 页 + 上传校验文件）。
- **规则配置前印刷不可开机**：先配好规则、真机扫码验证通过，再批量交印。→ 测试期用 体验版启动参数 / 编译模式模拟进入（welcome 已兼容 `?code=`）。
- 微信内扫码进小程序时链接在启动参数 `?q=`（urlencode）里 → welcome 已增 `?q=` 解析（取 `code=` 参数或路径最后一段），与 `?code=` / scene 三轨兼容。

## 14. 视频上传控制台：自建网页编排页

决策（2026-06-11）：课程视频上传与编排做**自建网页控制台**（课程→章节→课时→小段三层编排、拖拽排序、原地改名、分段上传、**草稿与发布分离**：`coursesDraft` 编辑、发布时覆盖 `courses`）。

原因：三层嵌套结构 CMS 表单做不了；电脑端传大视频远比手机顺手；草稿/发布分离让编辑过程不影响线上学员。视频存储最初用云存储，后由 §31 升级为腾讯云点播 VOD。

## 15. 控制台主轴 = 商品上新流水线（商品建档进自建控制台）

决策（2026-06-11，用户明确逻辑层级）：管理控制台以**商品**为主轴组织：创建商品 → 上传产品图片 → 填写 SKU → 上传编排配套教学视频 → 设计二维码卡片（可自定义尺寸）→ 批量生成二维码地址，**打包下载 SVG 设计图 + 地址清单**交印刷厂。

原因（收益）：

- 与真实业务动线一致：上新就是「一款商品走完六步」，比按工具分模块（课程/卡片各一摊）更不容易漏步骤。
- 商品图片在控制台上传后直接喂小程序商品页——真实素材替换灰占位有了正式入口。
- SVG 矢量交付印刷厂，配合「一地址一码」的既定工作方式（§13），印刷链路全自动化。

代价（与对策）：

- 商品建档、图片、SKU 的写路径全部收口到自建控制台的云函数。

## 16. 管理台形态升级：一比一所见即所得橱窗

决策（2026-06-11，用户提出）：小程序信息（排序、上下架、文案等「长什么样」的内容）的管理形态定为**一比一所见即所得**——控制台内嵌手机框预览（iPhone 17 比例，用户指定），与小程序同一份云端数据渲染，在画面上直接拖动/编辑，与右侧面板双向联动。

原因（收益）：非技术运营者零学习成本（看到的就是用户看到的）；数据本就同一份、设计 token 共用，等价渲染成本低；为「小程序信息全面可管理」铺路。

代价（与对策）：等价组件需随小程序 UI 改版同步维护 → 只复刻「可管理区块」关键视觉。

影响：products 的 featured 语义 = 首页橱窗位。

## 17. 代码按技术分层组织（package-by-layer），不按业务链重组

决策（2026-06-11，用户提出并拍板）：代码保持**按技术分层**组织，**不**改成按业务链分文件夹（package-by-feature）。每条业务链的整体视图由 `docs/业务逻辑架构.md` 提供——逻辑上集合、物理上分布。

原因：
- **硬约束**：① 每个云函数是独立部署单元，其「云端那一半」无法并入某条链的功能文件夹；② admin/agent 是独立构建部署的工程；③ 共享代码跨多条链复用，按功能切会被迫复制（破坏单一来源）或进 `shared/`（又散回去）。
- **软代价**：按功能重组要改全部 import 路径，回归风险高，不为整洁动工作代码。

影响：新增功能按各包的技术分层放置（小程序 `pages → lib → api`，云端按域进 `rewrite/cloud/src/functions/<域>/`），页内自用代码就近放页面目录；**业务链或状态机变化时，先改 `docs/业务逻辑架构.md` 再动代码**。

## 19. 客服 = 微信客服官方组件（R18）

决策（2026-06-30 定稿）：

- **渠道**：从「小程序客服」（`open-type=contact`，功能简陋）升级为独立**微信客服**，经同主体企业微信的自建应用托管；小程序四个入口统一走 `utils/customerService.ts` 的 `wx.openCustomerServiceChat`。
- **定位**：客服不只是聊天工具，是「微信生态多节点接住 + 统一 360 + 按意图分流」：订单/售后走微信客服（bot + 360 自动答）；钩织学习求助引导加企微做 VIP 私域（官方「联系我」插件沉淀，入口话术用功能性描述，专属感留到加好友之后，避开诱导红线）。
- **360 坐席工作台自建**：复用现有集合与数据，加 `getCustomer360` 聚合、坐席检索、RBAC。不买付费客服 SaaS（年费高、5 个坐席以上再议），不上有赞/微盟中台（锁数据、废掉自建投资）。理由：现有资产已覆盖 360 数据源的大半，自建最省、最灵活、数据自主。架构规则见 `docs/业务逻辑架构.md` 链 11。
- **承面**：外包坐席走自建独立工作台（承面 C，外包不进企微）；内部 VIP 走企微侧栏（承面 A，按需未做）。
- **身份桥**（external_userid → openid）是 360 的命门：小程序绑开放平台，经 unionid 反查。
- **微信小店＝分发渠道，不是交易引擎**：核心商品「材料包 + 激活码 + 课程」捆绑、激活链绑 openid，装不进小店；小店只宜引流款。
- **AI 选腾讯混元，时机押后**：真实咨询量起来、关键词兜不住再上。
- 配套新增：知识库（FAQ 单源）、满意度评分、会话质检、主动召回、UGC 照片内容安全。未做：支付投诉、换货、跨 openid 合并、客服侧风控等合规补全。

## 20. 物流方案（R17 + 发货合规）

决策（2026-06-15，用户拍板，先调研微信官方规范再定）：物流分**两件不同的事**，分别定。

**① 发货信息管理（强制合规·非选做）**：凡微信支付卖实物的小程序，支付后须向微信上传发货信息（`upload_shipping_info`，用小程序自己的 AppSecret，**与快递公司 API 无关**），否则订单资金冻结、无法结算。已接进发货链：admin 发货时经 `kit/shipping.ts` 自动上传，失败只告警、不回滚发货（业务逻辑架构链 5）。

**② 物流轨迹展示（R17）**：决策＝上 **快递100「快递跟踪」免费小程序插件**。理由：直连快递公司 API 难（要签约/资质），但聚合服务商（快递100/快递鸟）已对接 1000+ 快递，只给「公司+单号」即返回轨迹、**小店不用碰快递公司**；快递100 插件对第三方小程序免费、模板化几小时接入、小程序内直接看轨迹不跳出。**风险**：快递100 服务市场已下架，复制兜底常驻。

**③ 运单下单（物流助手·电子面单）跳过**：适合发货量大要批量打面单的店；卖家现手动用顺丰寄，初期不碰。

## 21. P3「安全处生成」codegen 范围：只给真有「status 字符串状态机」的域立册

决策（2026-06-24）：「一张状态声明表 → 生成类型/常量 + 对账守卫扫散落实现」的范式，**只给真有自有 status 字符串状态机、且多处写入需对账的域立册**，不为凑数立空册。
- 已立册：订单/售后、学习（码 unused→activated）、客服会话、SCM（见 `rewrite/shared`）。
- 不立册：进课确认 `activations.enteredAt`（null→时间戳的条件抢占，是并发闩不是状态机）。
- 再扩前置：新域先查「有没有一串自己的状态流转散在多个函数里需要对账」，有才立。

## 22. 故意不抽象：投机泛化默认拒绝（YAGNI / Rule of Three）

决策（2026-06-25，用户提「过度工程防治」并拍板）：本仓**默认拒绝投机抽象**——内联具体优先；新增接口/层/泛型/配置项须有当下真实需求，理由含「万一以后/方便将来」即删；相似两段先问「本质相同还是碰巧长得像」、宁可先重复，到 Rule of Three 第三次方向看清再提。横切方法论决策（与 §17 同级）：`CLAUDE.md`「防过度工程」是写码时的尺，本条答为什么、攒判例。

为什么需要这条：治理框架（根因账本 + 结构守卫）整套在**防「做得不够」**，每条守卫都逼把该做的做到；这套「每主张配守卫」范式自带反向风险——守卫越堆、抽象越厚。过度工程＝替用户没给的数字（规模/寿命/用途）瞎猜天花板：约束一旦明确（一次性脚本 / 3 个内部用户 / 半年必重写）就不该按企业级铺。且错误抽象比重复更贵——「碰巧像」当「本质同」合并，后续拆解代价高。

判例（本仓既有「故意不做」实例，后续同类决策引此为锚）：
- **S11 商品不引 xCounts**（`94c797b`）：草稿量小全量加载，计数/筛选/搜索前端做即诚实，不为「将来量大」预建后端聚合层。
- **cs 客服域不立 P3 空册**（§21 / `5d64446`）：查证无自有 status 状态机 → 不为凑数立册。
- **§11 CMS 按需暂缓**：当前无独有高频需求 → 不预装一套账号与维护面，将来真出现再装。

边界：**未来式 ≠ 投机式**。遇到「以后/预留/将来」先三分流：① 能追到需求清单、决策或用户明确意图＝保留；② 只有泛泛未来收益＝删或延后；③ 来源不明＝先问，不直接改。

为什么靠人（不配机器守卫）：「过度抽象还是必要抽象」是判断题、机器证不出（同根因 #8/#10 靠人类）。为它硬上守卫本身就是过度工程——用守卫自证。

6. **后台 admin + agent 一并重写，栈保留 Vue3+Vite**（现栈健康非病根，重写代码与信息架构）。
7. **旧铁律「永不重生成真机验过的运行时/UI」退役**：用户拍板 **UI 也可重设计**（可借 Skyline 转场/手势升级视觉交互），验收基准随新设计重建——工期与重新真机验收的代价已明示接受。

## 24. Clean Architecture 采纳边界：采宪法、拒样板（2026-07-04）

决策（2026-07-04，用户提《架构整洁之道》读书笔记问「重写规范是否遵循」，评估后拍板）：新线工程约定**采纳其五条宪法级原则、拒绝其样板级实践**。

**采纳（＝新线不变量）**：
1. **依赖方向单向且无环**（依赖规则+ADP）。这条同时印证 §17：书明言「架构关注依赖方向而非物理文件夹组织」。
2. **业务规则独立于实现、可脱离环境测试**——hermetic 内存桩纪律；现行行为的权威是测试。
3. **接缝处依赖反转、细节单点收口**——支付/告警/客服 qyapi 等平台接缝各收一处，这是「留云开发但保留将来迁自建自由度」（§23-4）的技术根据。
4. **框架不绑架架构**——弃 uni-app 的教训成文：框架当工具用，业务层不为框架便利倒灌。
5. **测试是架构一等公民**——完成只由机器判（`CLAUDE.md` 流水线第 3 步）。

**拒绝（与 §22 防过度工程铁律直接冲突，引为判例）**：

## 30. tab 页误触退出提醒：机制定选 `page-container`、`enableAlertBeforeUnload` 判废（2026-07-14·终结三次翻烧饼）

决策（2026-07-14，查官方文档、社区真机报告并对抗验证后定论）：

- **能做，但只有一条路**：tab 栈底页（首页/购物车/我·返回=退出小程序）的误触退出提醒**只能用隐形 `<page-container>` 的「再按一次退出」**，且**只可靠覆盖安卓返回键**。`wx.enableAlertBeforeUnload` **判废、不再用于本用途**。
- **为什么 `enableAlertBeforeUnload` 无效（双死因）**：① 它是"返回上一页"确认框、语义绑 `navigateBack`/左上角原生返回按钮，tab 栈底页无上一页；② 本 app `navigationStyle:custom`（home.json 自绘导航）**藏掉了它要挂的原生返回按钮**（社区证"只有非自定义标题栏才触发"）→ 首页永远不弹。真机已测出「无弹窗」。
- **为什么 `page-container` 有效**：拦返回看"本页有无武装容器"、**与栈深无关**，故栈底页照拦（`<page-container show overlay="{{false}}" duration="{{0}}" bindbeforeleave>`·基础库 ≥2.16.0）。武装时给 Page 注入 `position:fixed`、锁页面级滚动（overlay=false 不解锁）→ **内容须套 `<scroll-view style="height:100vh">`**。旧 uni-app 线（`packages/miniapp` useExitGuard.js）安卓真机验证过、是唯一带真机标签的结论。
- **平台天花板（任何机制都拦不住·非缺陷）**：胶囊「×」/ Home 键 / 上滑杀进程 / **鸿蒙 HarmonyOS**（官方明说不能拦）。iOS 边缘侧滑退出=未证实、须真机（可能半滑卡死/白屏）。
- **现行实现**：三个 tab 页用 page-container 三件套 + 整页套 `<scroll-view>`；判废 API 防回潮由 `rewrite/mp/tests/tabbar-exit-guard.test.ts` 锁住。**要撤掉退出提醒须先改本 §30**。

## 31. 视频转码管线拍板：腾讯云点播 VOD（2026-07-18·转码=播放丝滑第一杠杆的落地方向）

决策（2026-07-18，经可行性、成本模型、落地风险三轮调研）：

- **选型：腾讯云点播 VOD**（弃数据万象 CI）。三路证据同向：① 能力面——转码+自适应+雪碧图+封面一站（雪碧图正补 R36、封面补 poster 缺口，CI 的雪碧图只是截帧输出模式）；② 成本面——VOD 媒资存储 0.144 元/GB/月 vs 云开发容量 3 元/GB/月（20 倍差），CI 产物存回云开发桶会把最大省钱项吃掉；③ 风险面——云开发桶直绑 CI 无官方文档背书。转码后每学员每遍观看流量缩 4~8 倍（百学员月账约 187→30 元），转码费一次性个位数元/课。
- **「拖动画面实时跟随」定性为伪需求、正解=雪碧图预览**：微信 `<video>` seek 秒级无精确选项、iOS 回退 1s、`seekcomplete` Android 不可靠、生态零成功案例、微信自家 controls 都是松手才跳；抖音/B站/YouTube 的「拖到哪看到哪」全部是预生成雪碧图（官方文档/逆向证实）。播放器维持两段式拖拽（拖动只改显示、松手才 seek）。
- **架构**：平台接缝单点 `kit/vod.ts`（镜像 callFlow·守卫 `rw-vod-seam-single`）；`isVodFileId`（纯数字 FileId vs `cloud://`）判据单源 `@ldrw/shared`，播放分流/GC 删除/admin 转码中显示三处共用；Key 防盗链签名纯本地 md5（有效期 6h > mp 25min 地址缓存 + 课时长，< GC 24h 缓期）、playKey 未配 fail-closed url:null（守卫 `rw-vod-sign-fail-closed`）；上传=admin 浏览器 vod-js-sdk-v6 直传 + UGC 签名（云函数纯 HMAC 派发）+ procedure 自动触发任务流；转码感知=拉模式（admin「同步转码状态」on-demand DescribeMediaInfos·**刻意不配回调**——云函数无公网入口，不为此开 HTTP 访问服务）；发布闸 VOD_PROCESSING（传完≠可播·防伪成功）。**未配置全链自动回退云存储老路，配置填入即切换（零部署·灰度零风险）**；**帮助视频线恒走云存储不迁**——其播放侧只认云存储 fileID（无转码同步无发布闸兜底），故共用的 `uploadVideo` 走 VOD 须显式 opt-in、默认老路。
- **运营模式变化（已知代价）**：上传完须等转码（1-2 分钟短段几十秒到几分钟、100 段自动排队约几十分钟、大半被上传时间掩盖）才能发布；发布前多一步「同步转码状态」。
