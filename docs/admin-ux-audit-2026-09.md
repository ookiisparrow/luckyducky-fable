# 运营控制台 UX 审查（2026-09）

> **只审不改。** 本文是给赵老板看的白话清单：后台哪里别扭、哪里容易点错。**没有改任何业务界面代码。**
>
> 审的是 `rewrite/admin` 控制台（侧栏 + 主要页面文案与交互）。对照店务：查单、发货填运单、退款审批、改销量、二维码按批。
>
> **怎么审的**：通读路由、侧栏、主要页面和按钮文案，并核对云端「点了后台会不会立刻对顾客生效」。**没有用真口令登录生产、没有在浏览器里实点。** 窄屏结论来自布局代码，不是真机截图。

---

## 先说结论

- **没有发现「一点就亏钱、后台还拦不住」的洞。** 退款、发货、金额异常禁发，服务端都有闸。
- **真正伤日常的，是找错门、以为存了其实顾客没看到、以及运维页和店务页搅在一起。**
- 下面按「先看重的」排序，共 **18 条**。重复的已合并。审美偏好单独收在文末，不当成必须修。

### 店规对照（审查时特意看了）

| 店规 / 背景 | 后台现状 |
|---|---|
| 优惠券等测试功能不该出现在给顾客的正式版 | **后台没有建券、发券入口**（没有搅进来）。顾客端那条「占位减 20 元」是另一条线，不在本次后台清单里。 |
| 发货：填好运单号即确认 | **就是这么做的**（订单抽屉回车 / 工作台扫面单即提交）。下面不当成「必须加确认框」；只标扫错码的剩余风险。 |
| 暂不向顾客收集手机号 | 登录不采手机号。订单里看到的电话来自微信收货地址（发货要用），列表还做了掩码。**不是违规采集。** |

## P1 · 常踩、容易做错事

### 1. 两个都叫「发货」，看板还只指其中一个

| | |
|---|---|
| **在哪** | 左侧「订单履约」：`订单发货`（`/orders`）和 `发货工作台`（`/fulfill`）。数据看板「待发货」瓦片只跳到 `/orders`。 |
| **怪在哪** | 一个是「查单、补录运单、改单号」；一个是仓里「拣货 → 打箱贴 → 扫码发」。名字都带「发货」，新来的人会点错。看板数字更新了，工作台还要自己点「刷新队列」才进新单，两处「待发货」不是同一画面。 |
| **会伤到谁** | 店主、仓里发货的人 |
| **严重度** | P1（客观怪） |
| **建议方向** | 侧栏改成一看就懂的一对名字（例如「查单 / 补运单」和「仓内发货」）；看板待发货旁写清「仓内流程请去发货工作台并刷新队列」。 |

### 2. 改价、改销量显示「已自动保存」，顾客端往往还是旧的

| | |
|---|---|
| **在哪** | `商品管理`（`/products`）点「编辑」后的表单：价格、划线价、销量与名称排在同一格。保存提示是「自动保存中… / 已自动保存」。 |
| **怪在哪** | 自动保存只写入**草稿**。顾客小程序看到的价格和「已售 N」，要再走一次「上架 / 重新上架 / 更新上架信息」才会变。销量还是手填展示数，不是真实订单加总；填 0 则详情页不显示。运营容易两种错：①以为改完顾客立刻看到；②改完忘了再点上架。 |
| **会伤到谁** | 改价的店主；看「已售」的顾客（展示数失真） |
| **严重度** | P1（客观怪 · 文案与真实行为）。**不是**「改一下顾客立刻按错价下单」——发布面有单独一步。 |
| **建议方向** | 价格/销量单独成一块，写明「先存草稿，上架后顾客才看见」；在售商品改完给一个醒目的「同步到小程序」而不是藏在「⋯」里。 |

### 3. 「上架」有三套说法，在售商品菜单里还有「重新上架」

| | |
|---|---|
| **在哪** | 商品列表：筹备中「上架」；已下架「恢复销售」；在售主按钮是「下架」，「⋯」菜单里还有「重新上架」。上新向导顶上还有「更新上架信息」，点下去确认文案是「确认上架？」。 |
| **怪在哪** | 商品已经在卖，菜单仍写「重新上架」，向导确认还问「确认上架？」。三套词对应三套动作（第一次上架 / 把停售的卖回去 / 把草稿同步到已在售的小程序），店主分不清点哪个。 |
| **会伤到谁** | 改完价或图、想「同步到小程序」的人 |
| **严重度** | P1（客观怪） |
| **建议方向** | 在售态不要再用「上架」；改成「把刚才改的同步到小程序」，确认文案写清「顾客将看到新价格/新图」。 |

### 4. 二维码一条流水线，三个名字、拆在两个菜单组

| | |
|---|---|
| **在哪** | 侧栏「商品与上新 → 卡片设计」（`/cards`）；侧栏「系统 → 激活码批次」（`/batches`，页标题却是「二维码批次」）；上新向导第 5 步「二维码卡片」、第 6 步侧栏写「码批次与印刷包」、向导里写「码批次」。 |
| **怪在哪** | 同一件事：画卡面 → 定稿 → 按批出码 → 导出给印刷厂。入口名三套，第 6 步做完「完成」却回到商品列表，下一步（出码/印刷包）在「系统」组里。设置页还写着「激活卡双面设计器随印刷批补齐」——设计器其实已经有了，这句话是过时的。 |
| **会伤到谁** | 第一次按批出码、对接印刷厂的人 |
| **严重度** | P1（客观怪） |
| **建议方向** | 对外统一叫一个名字（建议「激活码批次」）；批次挪到「商品与上新」或向导第 6 步做完直接留下；改掉设置页那句过时说明。 |

### 5. 客服拿着订单号，会话页搜不到聊天记录

| | |
|---|---|
| **在哪** | 「客服 360 → 客服会话」（`/conversations`）三个框：openid / 外部用户号 / 关键词。「客户 360」（`/customer360`）才能用手机号、订单号搜。客户 360 打开后**没有**「去看会话」按钮。 |
| **怪在哪** | 客诉常见开场是「这单号怎么回事」。会话页不认订单号和手机号，还把内部编号（openid）放在第一格。路径变成：先去客户 360 搜 → 抄一串内部号 → 再回会话页搜。侧栏组名「客服 360」、子项「客户 360」也是内部叫法。 |
| **会伤到谁** | 一线客服、外包坐席 |
| **严重度** | P1（客观怪） |
| **建议方向** | 会话页做成一个框，自动认手机号/订单号；客户 360 加「查会话」。组名改成「客服工作台」，「客户 360」改「客户全景」。 |

### 6. 对账页一屏三套数字，还写着 GMV

| | |
|---|---|
| **在哪** | 「订单履约 → 财务对账」（`/reconciliation`）：横幅「全账累计」、上面一排「全账累计」KPI、下面一排「区间收支」KPI。文案用「应收 GMV（已付）」。内部异常明细只有单号，点不进订单。 |
| **怪在哪** | 同一屏三个口径，店主/小财务容易拿错数去对外报。看板用的是「成交额（已付）」，这里换成英文缩写。危险项「微信收了钱、我方没单」标红是对的，但没有「接下来怎么做」的指引。 |
| **会伤到谁** | 看账的店主、对账的人 |
| **严重度** | P1（客观怪） |
| **建议方向** | 默认只展开「当前查询这段时间」；「全账累计」收进折叠区；GMV 改成和看板一样的「成交额（已付）」；异常单号做成可点进订单/退款。 |

### 7. 金额对不上时，「补录实付」弹出浏览器旧式对话框

| | |
|---|---|
| **在哪** | 订单发货页，金额异常单：「去核对」是页面里点两次确认；「补录实付」弹出浏览器自带的输入框，文案是「实际到账金额（元）？……将作为该单退款金额的依据」。 |
| **怪在哪** | 解除禁发做得认真，补录退款依据金额却像系统提示窗，没有「你填的是 xx.xx 元」预览，也容易误粘贴。风格和旁边的「去核对」完全不像一家人。 |
| **会伤到谁** | 店主、对账的人（这笔会变成退款上限依据） |
| **严重度** | P1（客观怪） |
| **建议方向** | 补录也做成和「去核对」同级的页面确认：数字框 + 大字预览金额 + 再点一次。 |

### 8. 「系统」菜单把日常店务和运维诊断堆在一起

| | |
|---|---|
| **在哪** | 侧栏「系统」八项：系统巡检、异常监测、外包账号、激活码批次、外部后台、系统设置、人工配置清单、审计日志。客服组里还有「节点诊断」（实际是编辑学员卡住时的话术，不是查某个客户的故障）。 |
| **怪在哪** | 日常要办的「出激活码、建外包号」和「巡检 / 异常 / 审计 / 去腾讯云」没有分层。新来的人可能从「外部后台」走进微信/云开发控制台。节点诊断的名字像排障，实际是改话术。 |
| **会伤到谁** | 店务运营、新上岗的人 |
| **严重度** | P1（客观怪） |
| **建议方向** | 系统组拆成「账号与批次 / 运维观测 / 外链」；「节点诊断」改名「学员卡点话术」，或挪到课程管理旁边。测试向的页加「非日常」标记。 |

### 9. 进销存：左边菜单顺序和页顶流程条顺序是反的

| | |
|---|---|
| **在哪** | 侧栏进销存：总览 → 物料 → **采购 → 外协 → 配方 → 备货**。页顶流程条（`ScmFlowTabs`）：物料 → **配方 → 备货 → 采购 → 外协**。总览页自己没有这条流程条。 |
| **怪在哪** | 同一套工作，两处「下一步」对不上。从总览点「去结算」跳到外协页，不会帮你滚到对应织女。物料页流水类型还直接显示英文码（如 `purchase_in`），总览却写成「入/出」。 |
| **会伤到谁** | 管仓库、管采购的人 |
| **严重度** | P1（客观怪 · 认路，不是钱链漏洞） |
| **建议方向** | 侧栏顺序跟流程条对齐；总览也挂同一条流程条；「去结算」带着人落到那一单。 |

### 10. 「页面内容」改完立刻对顾客生效，含「激活后不可退货」法务句

| | |
|---|---|
| **在哪** | 「商品与上新 → 页面内容」（`/page-content`）页头写着「编辑即自动保存、保存后立即生效」。「欢迎与激活」签有警示语，默认「激活后不可退货，请确认后再激活。」卡片设计的卡背还有另一句类似提示。后台**没有**名叫「锁课」的开关——锁的是顾客进课这个动作，文案散落在两处。 |
| **怪在哪** | 和商品草稿不同：这里改一个字，小程序马上变。法务句可以在欢迎页改一处、卡面忘改另一处。标签还写着内部编号「W1 恭喜屏」。 |
| **会伤到谁** | 改文案的人；看到两套说法的顾客/客服 |
| **严重度** | P1（客观怪 · 合规文案） |
| **建议方向** | 警示语单源、两处一起改；页头区分「立刻对顾客生效」和「先存草稿」；不要用 W1/W2 这种内部编号当标题。 |

## P2 · 别扭、会浪费时间或偶发点错

### 11. 「编辑排序」长得像按钮，点了没反应

| | |
|---|---|
| **在哪** | 左侧导航小标题旁的「编辑排序」芯片，鼠标悬停提示「侧栏拖拽排序即将支持」。 |
| **怪在哪** | 看起来能点，实际点不了。 |
| **会伤到谁** | 每个打开后台的人 |
| **严重度** | P2（客观怪） |
| **建议方向** | 没做就藏掉，或改成灰字「即将支持」。 |

### 12. 上新向导前三步是同一张大表

| | |
|---|---|
| **在哪** | `/products/:id/wizard` 第 1–3 步（产品图片 / 商品信息 / SKU）。侧栏步名第 4 步是「视频上传」，向导顶栏是「教学视频」。 |
| **怪在哪** | 切步只改标题和网址，表单还是封面+价格+规格全开着。第 6 步「完成」回商品列表，不带到出码。 |
| **会伤到谁** | 按向导一步步走的新运营 |
| **严重度** | P2（客观怪） |
| **建议方向** | 前三步合成一步，或按步只展开该步字段；完成按钮指向出码页。 |

### 13. 退款：同意是大紫钮；「越规退款」和刷新按钮坐在一起

| | |
|---|---|
| **在哪** | 「售后退款」（`/refunds`）。同意前要勾「已收到包装并验收」「激活卡未拆封」。页头 ghost 按钮「越规退款」。抽屉里露出 `courseId`、`ENTERED_NOT_REFUNDABLE` 这类内部字。 |
| **怪在哪** | 退钱和普通主按钮一个颜色。勾两个框后一键就发起，没有「再确认退 ¥xx」最后一屏（服务端仍会拦进课不可退）。越规是高危能力，入口却和「刷新」并列——误点后还有查找/原因/勾选，不是一击即退。 |
| **会伤到谁** | 审退款的人、店主 |
| **严重度** | P2（钱相关醒目度 · 客观偏怪）。服务端有闸，不升 P0。 |
| **建议方向** | 同意退款改危险色或把金额再放大；越规收进「更多」并写权限说明；内部代号改成「进课后不可退」。 |

### 14. 给店务看的字里夹着内部黑话

| | |
|---|---|
| **在哪** | 商品「关联课程」占位 `course-xxx`；客服搜索 `openid`；满意度表头「定位键」；审计搜索「action 前缀（如 save）」；对账「GMV」；进销存流水英文类型码；登录失败可能出现 `VITE_ADMIN_API`。 |
| **怪在哪** | 同一概念多叫法（外部用户号 / 定位键 / openid）。坐席不知道 openid 从哪抄。 |
| **会伤到谁** | 非技术运营、外包 |
| **严重度** | P2（客观怪） |
| **建议方向** | 对外中文，内部号放第二行或问号说明。SKU、CSV 这类行业词可留，加一句人话即可。 |

### 15. 箱贴「已打印」只记在这台电脑的浏览器里

| | |
|---|---|
| **在哪** | 发货工作台打印步的提示：「打印记录只记在本机浏览器；打废的单点「已打印」徽标取消」。 |
| **怪在哪** | 换电脑、清缓存、两人两台机，对不上谁打过标。可能重复打或漏打。货不会因此自动发出（发货仍要扫码且服务端校验），但仓内会乱。 |
| **会伤到谁** | 仓里发货的人 |
| **严重度** | P2（客观怪；大促两人协作时接近 P1） |
| **建议方向** | 页头常驻这句；需要多人协作时再考虑记到云端。 |

### 16. 笔记本窄窗：表被裁、侧栏占掉一截还不收

| | |
|---|---|
| **在哪** | 壳层左侧栏固定约 248 像素，没有收起。订单/退款等宽表；全局表样式是裁切而不是左右滑。只有少数页（橱窗、部分进销存、配置清单）写了窄屏换行。 |
| **怪在哪** | 分屏、小笔记本上，操作列和金额列可能被切掉。后台按桌面设计，**不是**给手机管店用的。 |
| **会伤到谁** | 用笔记本分屏办公的人 |
| **严重度** | P2（客观怪） |
| **建议方向** | 侧栏可收起；表外包一层左右滑动。不当成要做手机版后台。 |

### 17. 知识库「保存整册」一键覆盖；勾「精选」会给顾客看见

| | |
|---|---|
| **在哪** | 「客服 360 → 知识库」（`/kb`）。页头「保存整册」「载入预设 FAQ」。行上有「精选」勾选，说明只写在鼠标悬停里：会下发到小程序播放页求助区。 |
| **怪在哪** | 删一行要点两次，保存整册（整本覆盖、影响机器人和坐席）反而不确认。精选误勾 = 顾客立刻看到这条 FAQ。载入失败时空表被门控，不会一保存把库清空——但仍可能把改残的整本写上去。 |
| **会伤到谁** | 改 FAQ 的人；看到错 FAQ 的顾客 |
| **严重度** | P2（客观怪 · 有载入门控，不升 P0） |
| **建议方向** | 保存前摘要「将写入 N 条」；「精选」旁常驻「会展示给顾客」。 |

### 18. 看板「今日无待处理」不准确；告警行展示难读的内部编号

| | |
|---|---|
| **在哪** | 数据看板（`/`）：待办清零时写「今日无待处理事项」；钱链告警把原始 id（有的带 `__`）直接列出来。发货工作台一次最多装约 25 页订单，触顶有提示，但角标仍可能显示偏小的「待发货 N 单」。 |
| **怪在哪** | 待办其实是「当前还没处理完的」，不是「今天才发生的」。告警编号人眼读不懂。「去处理」有时带订单号预填，但不保证落到那一行售后。 |
| **会伤到谁** | 看看板派活的店主 |
| **严重度** | P2（客观怪） |
| **建议方向** | 改成「当前无待处理」；告警显示订单号+商品名；工作台触顶时角标写成「至少 N（列表不完整）」。 |

## 符合店规、只标剩余风险（不列入必改）

**填运单 / 扫面单即发货。** 订单抽屉：运单框回车 = 提交。工作台第 3 步：扫快递条码即发货，没有「再确认」按钮。这是店规。剩余风险是扫枪扫错码、或回车太快。服务端会拦退款中、金额不符、状态不对的单。若以后要加缓冲，应是「显示 2 秒再提交」这类，而不是推翻店规再弹一次「你确定吗」。

**「测试二维码」**（激活码批次页）：给印刷前用手机微信扫一下，验落地页。不是给顾客的测试券。若怕「测试」二字吓人，可改成「量产前扫码验码」。

## 做得好的（对照着看，免得以为处处不行）

- 退款同意前必须勾两个人工验收框；越规要填原因并勾「我已知晓越过常规流程」。
- 涉及退款的订单，发货按钮变成红字「勿发货」，服务端也会拦。
- 金额异常「去核对」是页面里点两次，不是一击解除。
- 商品下架/删除、课程发布（「老学员立即生效」）、外包停用，多数已有「按钮字变成确认？」的两步。
- 设置页对没做的能力写「规划中（未接入 · 不做假开关）」，没有假开关骗人。
- 登录页会把「坐席工作台」和「管理后台」分开说。
- 退款空列表会告诉你「别的栏还有 N 单」，避免待审核为 0 时以为没事。
