# 003 重写定标：原生栈、成交留小程序、本仓=生产源

## 决定
整体**重写**（非局部重构）：微信端 = **原生 TypeScript + glass-easel**；后端留云开发但函数重写；web = Astro 内容站（GEO 语料），**成交全留小程序**；admin/agent 重写仍 Vue3+Vite；线上以本仓 `rewrite/` 为**唯一生产源**，冻结旧版后同 AppID 整体替换。

## 背景
旧线定性为 demo 派生全局重构产物；多端/uni-app 前提已不成立。支付连接器等锁在云开发控制台，留平台切换风险最小。小程序对站外搜索不可见，需自控 web 语料，但 H5 商城不做。

## 备选
1. 在旧线上持续重构  
2. uni-app 多端 + H5 商城  
3. 按端选栈整体重写 + 内容站、成交留小程序（现案）

## 为何不选
1. 非根本枷锁清不掉，成本高于重写。  
2. 多端目标已放弃；H5 商城证据弱且破坏微信原生单源。  

## 后果
- 废止旧 ADR §1 uni-app、§2「暂不用 TS」。  
- T1：交易核心只连云，不松；分发可接小店/搜一搜，不做 H5 成交。  
- 部署真实改生产云；`README`/`agents-entry` 须声明生产源。  
- 改栈或做 H5 成交前，须先改本记录。
