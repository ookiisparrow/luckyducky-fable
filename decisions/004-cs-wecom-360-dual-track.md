# 004 客服：企微内微信客服 + 360 自建 + 双轨分流

## 决定
客服承面走**企业微信内管理的微信客服**（非简陋小程序客服、非付费一线 SaaS）；**360 工作台自建**；意图**双轨**——订单/售后走微信客服+360，钩织学习求助引导加企微私域；微信小店仅**分发渠道**、不迁交易/课程引擎。

## 背景
需求远大于聊天工具：要统一 360、多节点、可外包。现有 CloudBase 数据已覆盖大半 360 源；付费一线贵且锁数据。材料包+激活码+课程绑 openid，装不进小店结算。

## 备选
1. 仅小程序客服（open-type=contact）  
2. 采购付费一线 / 有赞微盟中台  
3. 企微微信客服 + 自建 360 + 双轨（现案）  
4. 小店当交易引擎

## 为何不选
1. 功能简陋，已升级否决。  
2. 年费高、数据被攥、废自建投资。  
4. 与自建订单/激活/课程单源冲突。  

## 后果
- 凭证面在企微自建应用；勿独立端↔企微来回切。  
- `getCustomer360` + RBAC/审计守卫；外包走自建 agent 台。  
- 小店券/小店订单引擎路线默认否（见 007）。  
- 改承面采购或小店引擎化前，须先改本记录。
