# 006 P2 威胁模型：防 AI 误操作，非防恶意

## 决定
流水线/审查守卫的防线目标是**防 AI 意外出错与幻觉**，不是防同机恶意攻击者；在「只读审查包 + prompt 约束 + 双票 + 人工闸 + 事后审计」已充分的前提下，**不因黑名单可绕过、同 OS 用户可碰活仓等架构极限继续无上限打回**。

## 背景
P2 组件经三轮双票打回，已修 15 类真实缺陷；残余限制（黑名单本质、同用户可篡证据）要完整技术隔离需容器/独立用户，单人本地场景成本不合理。

## 备选
1. 追到容器/chroot/独立用户级隔离再收工  
2. 接受「防意外」威胁模型并记录残余风险（现案）  
3. 放弃双票/守卫，只靠人

## 为何不选
1. 成本与单人本地场景不匹配。  
3. 已验证双票能揪出真实缺陷，不宜丢。  

## 后果
- 后续审查以「意外误操作」场景设计用例，不以红队破黑名单为收工条件。  
- 残余风险记账在案；要升威胁模型须先改本记录。
