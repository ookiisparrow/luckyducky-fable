# PL-002: 支付异常（payment_exception）全链路 + 审核修复复核

## 变更范围（相对 HEAD 上一提交的未提交改动，本次一并提交）

### A. 支付异常态引入（功能主体）
- `payCallback`：到账金额与订单金额不符时不再照翻 paid，改为 pending/closed → `payment_exception`
  （记录 expectedFee/paidFee/paymentMismatchDirection；pending 路径回补库存、closed 路径不重抢；
  重复回调幂等不重复告警；`initial` 读前置用于算 mismatch）
- `shared/order.ts`：payment_exception 入终态 + 两条 transitions
- 各端标签穷举补全：shared statusLabels / mp mapOrders + order 页 BANNER + order-list TINT / admin mapMoney / cs kfCallback STAT
- `admin`：异常单红标（badgeTone/mismatch 行类）、清 mismatch 按钮对异常单隐藏 + 服务端 clearFeeMismatch 拒绝、
  mapSystem 对账文案
- `overrideRefund`：放行 payment_exception，退款分母改用 paidFee（asFen 校验·脏值拒 PAYMENT_AMOUNT_MISSING）
- `inspect`：stuck-order 新增异常单扫描（按 paidFee 判已退清）+ money-conserved 异常单分母用 paidFee
- `transition`：函数 patch 副作用延后到 CAS 成功后（当前态不在 from 即早退，防重复回调触发告警副作用）

### B. 审核修复（本上下文提交内）
1. inspect 异常单「已退清」分母：裸 paidFen → 逐行分摊上限和（refundableCapFen 支持 paidFee 覆盖）——
   消灭多行订单分摊取整缺口导致的永久假死信（与 refund_required 批K 修复同源）
2. inspect 异常单退款额脏/缺：fail-closed 报出（okMoney 提取文件级共用），不再被 NaN 污染成漏报
3. inspect stuck-order severity：exceptionIds 纳入 high（异常单＝钱已收待人工，与死信同级）
4. 新增 `recordPaidFee` 补录实际到账金额（退款死胡同出口）：仅 payment_exception 可补、正整数分校验、
   条件更新防并发、留痕（paidFeePrev/RecordedAt/RecordedBy）；前端订单列表「补录实付」按钮；cap refund:manage
5. docs/业务逻辑架构.md 措辞对齐：「进课均冻结」→ 码随货交付（兑课入口本身不校验订单状态·改线上发码前须补闸）
