# 02 · 数据库 / 云存储权限期望表（根因#9）

> 「敏感写一律走云函数」的前提是客户端不能直接读写库。这道闸设在控制台，代码和 CLI 都读不到安全规则，所以是 git 外资产，靠人照本表核。集合名单以 `rewrite/shared/src/collections.ts` 的 `COLLECTIONS` 为准；守卫 `rw-collection-perm-registered` 保证每个集合在本表有一行。

## 期望：所有集合一律「仅管理端」（adminonly）

- 小程序不直接读库（全走云函数），所以没有集合需要公开读。**「所有人可读写」「仅创建者可读写」都不行**：后者客户端仍能读写自己那条（曾有 13 个集合因此可写）。
- 原来标「所有人可读」的 `courses` 会让 `videoFileId` 被客户端直查泄露（付费视频漏口）。商品图、头像的显示走**存储**的公开读，与集合权限无关。
- **动态新建的集合默认是 private（仅创建者）＝真洞**（`rateLimit`、`wxBills` 出过事）：首写后或预建时就锁。

**核对与上锁**：
- 查：`tcb permission get collection -e <env>`（`adminonly` ✓ · `private` ✗ · `readonly` ✗）
- 锁：`echo y | tcb permission set collection:<名> --level adminonly -e <env>`（交互确认须管道喂 y）
- 实测：客户端直接 `add`/`get` 各集合一律被拒（-502003）才算过。

## 云存储

- `products/` `avatars/`（商品图 / 头像，公开展示）：仅创建者可写、所有人可读。
- `videos/`（付费课视频）：云开发存储规则只认创建者、不认路径（`resource.path` 写法报 InvalidParameter），做不到「products 公开读 + videos 私有读」，所以**保护靠 fileID 拿不到**：
  1. `getCourses` 剥掉 videoFileId（只返 `hasVideo`）；
  2. `getPlaybackUrl` 鉴权后只发短时效地址；
  3. `getMyCourses` 不带 fileID；
  4. `courses` 集合仅管理端，客户端直查被拒。
- 核对：客户端 `db.collection('courses').get()` 被拒（-502003）；未购课账号请求付费段 `getPlaybackUrl` 返 `NOT_ENTITLED`。
