# 03 · 复合索引期望表（根因#9）

> **这是什么**：`rewrite/cloud` 里需要索引才不退化全表扫描的查询形状——「where + orderBy」复合查询、热路径的多字段等值查询、定时清理的范围删除——的**建索引靶**。云开发数据库在数据量上去后，查询没有匹配索引会退化全表扫描（慢/超时）。索引建在控制台、git 管不到——与 `02-库权限期望表.md` 同性质的 git 外资产正册。
> 本表是「量上来前照单建」的期望态。**变更纪律同 README：先改本表、再动控制台。**
> **怎么建**：云开发控制台 → 数据库 → 选集合 → 索引管理 → 新建复合索引，字段与方向照下表。控制台地址：https://tcb.cloud.tencent.com/dev
> **方向说明**：MongoDB 系复合索引支持整体反向遍历（(a↑,b↓) 同时服务 (a↓,b↑)），且前缀字段为等值过滤时末位排序字段正反都可用——下表已按此合并同型条目；只用到前几个字段的查询由同集合更长的索引按前缀覆盖，不另建。
> **出处**写「文件 · 函数名」（路径相对 `rewrite/cloud/src/functions/`，`kit/` 开头的相对 `rewrite/cloud/src/`），不写行号——行号随改动漂移；代码改查询形态时同批更新本表。

## 不需要复合索引的（附排除理由，防误建）

- 纯 `orderBy` 无 where 的读（activations/assemblyOrders/productsDraft/inspectRuns/wxBills/dashboard 投影读、app/actions/learning.ts getCourses）——单字段排序，默认可用或建单字段索引即可。
- `kit/inventory.ts getInventory`——where 与 orderBy 同为 `productId` 一列，非跨字段复合。
- `adminApi/actions/orders.ts` 的 `{_id: q}` 直查、各处 `{_id, status}` 条件写——主键天然索引。
- 小集合的等值查（adminConfig、agentState、materials、products 按 `id`/`courseId`）——文档数个位到百级，全扫无感。
